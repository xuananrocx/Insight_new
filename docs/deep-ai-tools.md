# 深度 AI：主动查阅知识库

现有 `deep_ai` 入口使用原生工具调用。AI 增强、基础检索、深度检索不变；旧的固定深度流程保留在 `src/qa/deep_ai.py`，不再从界面调用。新流程位于 `src/qa/tool_agent.py`。

## 使用

在设置中选择默认个人或团队 API，点击“检测工具调用支持”。检测进行一次无知识库内容的工具请求及结果回传；不会更改默认 API。支持 OpenAI Chat Completions、Responses、Anthropic 和 Anthropic Arch。兼容地址是否真正支持工具调用以检测结果为准。失败不自动切换提供商，界面会建议使用 AI 增强。

OpenAI 兼容地址仅填写域名（例如 `https://api.example.com`）时统一补全为 `/v1`，连接测试、普通回答和深度 AI 使用相同解析规则。已填写的自定义前缀与 `/chat/completions`、`/responses` 完整端点保持原意；不自动尝试其他域名或协议。这避免域名根路径误入网关的其他转换接口，出现 `input[0].tools[0].name` 缺失等误导性错误。

选择“深度 AI”后，模型可检索、换词补查、查找文档、读取目录及按章节分页阅读。回答默认可加入明确标注的通用知识和推断。设置中的“仅依据知识库回答”默认关闭，开启后通过提示约束回答来源；它不是对模型事实正确性的保证。

工具动作、计数和耗时出现在现有默认折叠的思考过程里，不展示模型内部思维。引用显示仍由原来的开关控制。模型调用与查阅记录在当前用户的 AI 日志中，运行异常进入系统日志，不写入操作审计。

设置 → 深度 AI 的“API 失败重试次数”默认 5，可选 0–10；按当前账号保存于浏览器，与“仅依据知识库回答”采用同一偏好机制。次数指首次调用之外的重试次数，每个模型请求最多共 6 次尝试。仅重试连接/传输异常、请求超时以及 HTTP 408、429、500、502、503、504；不重试鉴权、参数和工具协议错误，不切换 API。等待采用 1、2、4、8、8 秒退避，并遵守服务端数字形式的 Retry-After。重试及等待都计入整轮预算，预算不足时可能未用完次数就结束。思考过程显示重试进度，每次失败日志保留 attempt/max_attempts。

流式回答一旦收到正文，不自动重放整个请求；中断时保存部分答案，避免重复内容。完整成功、部分完成、失败和用户停止通过 `answer_result` 过程记录保存到会话，刷新后可恢复；连接无结束事件便断开也视为失败。引用校验通过不代表整轮回答完成。系统日志的问答结束记录包含 session、turn 和 outcome，可与中间失败的模型调用区分。

失败调用的“错误详情”保留调用编号、用户/会话/API、目标接口、请求参数摘要、阶段、HTTP 状态、响应错误摘要和异常链。系统日志可按同一 `call_id` 查找 `request_start`、`connect_start`、`request_headers_sent`、`response_received`、`request_failed`。环境代理配置只说明 HTTPX 可读取的代理设置，实际连接目标以 `connect_host` 为准；连接复用时可能没有新的连接事件。收到 HTTP 错误不代表已经到达模型服务商，需结合连接目标和响应头判断。日志不记录鉴权请求头，错误摘要中的密钥、URL 凭据与查询参数会脱敏，错误正文最多读取 8 KiB，摘要限长。新的诊断只能用于更新后的调用，旧日志中丢失的响应正文无法补回。

## 边界和预算

- 工具固定为 `get_kb_overview`、`search_knowledge`、`list_documents`、`get_document_outline`、`read_document`，只能读取当前用户有查询权限的当前知识库。查询权限不赋予原文件下载权限。
- 模型不能传入用户、知识库、文件路径或其他 API。工具参数经过类型、长度和范围验证。每次调用、结果回传、流式输出都重新检查知识库和 API 权限。
- 默认最多 6 轮、12 次工具请求、每次检索最多 8 条、每页原文最多 6000 字符、总耗时 180 秒，保留最多 60 秒生成答案。工具顺序执行，避免争用本地向量模型和引入引用编号竞争。重复调用缓存并终止重复循环。
- 180 秒是模型与工具工作的预算；预算到期后仅允许有界的权限/版本校验和连接清理，每项最多 5 秒。数据库校验在线程中执行，正文小块合并后逐批校验和推送，不对 SSE 空行、推理元数据重复查询权限。取消重试等待不会发起下一次请求。
- 可通过已有 `qa.deep_ai` 配置调整 `max_rounds`、`max_tool_calls`、`context_chars`、`max_tokens`、`total_timeout_seconds`；旧配置中的 `context_chars` 等限制继续生效。
- 超时工具的结果不会进入后续上下文。达到查阅预算后用已读证据生成答案；最终生成失败时保留已生成内容或已找到的原文。停止会取消模型连接并阻止后续工具执行，运行中的同步底层操作在下一个检查点退出。

## 原文与引用

复用已入库的文档块，无需重新向量化。文档级检索使用关键词匹配，知识库检索使用已有语义与关键词融合；语义服务失败时尝试关键词检索并说明限制。已删除的关键词索引项不作为证据。

目录从章节元数据生成，章节缺失的旧文档按保存的文件级块顺序读取。相邻块仅合并可证明的精确重叠，分页返回继续位置。目录与阅读会明确提示索引缺失、未成功解析和内容截断；无法读取图片、OCR 未提取内容或原索引从未收录的文本。单文档最多读取 10000 个块以限制内存，超过时标记不完整；需要完整恢复的旧资料应重新导入。

每条实际传给模型的原文由程序分配引用编号，保存文档 ID、内容哈希、原始块 ID、章节、页码（若有）、偏移及最多 6000 字符的原文快照。目录、文件名和概览不分配引用。历史会话仍展示当时保存的快照，当前文档更新不会改写旧引用。

在本次回答前后检查文档版本和成员块；发现阅读中的文档更新或删除会要求重新提问。非法引用编号会被移除。此验证只证明引用存在及版本一致，不声称完成逐句事实核验。文档提示注入、通用知识冒充事实等风险通过提示约束和只读工具边界缓解，仍应按引用核对重要结论。
