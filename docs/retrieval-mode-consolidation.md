# 检索模式精简

界面仅显示基础检索、增强AI、深度AI，入口标题保持“检索模式”，新会话默认增强AI。

- 基础检索：直接展示知识库片段。结果中的“扩展检索”复用原 deep 检索的重排、概念扩展及相邻段落补全，不生成聊天回答。向量检索仍可能使用嵌入服务。
- 增强AI：保持原 ai 的检索和流式作答流程。
- 深度AI：保持原 deep_ai 的自主工具调用和流式作答流程。

## 扩展检索

复用 POST /api/v1/qa/ask_stream，传 operation=expand、mode=deep 及原 session_id、turn_id、question、kb_scope。服务端校验所有权、当前知识库权限和原问题。成功后在 done 事件中返回已保存的 expansion（sources、trace、completed_at）。普通 ask 请求的处理流程保持原样。

扩展不新增问答，不覆盖原 sources、trace、answer、mode，不改变下一轮模式。结果默认显示最新扩展，基础结果可单独展开查看。支持取消、重新扩展；失败或取消不会清空已有结果。取消停止等待及后续发布，不强杀底层同步检索线程。保存完成是提交点，若此时网络断开，刷新可恢复服务端已保存的结果。

同一问答在浏览器和单个后端进程中有重复执行保护。多进程部署时须先将后端运行锁迁移为跨进程锁。

## 历史及数据兼容

仍接受 basic/deep/ai/deep_ai 四个历史枚举。显式 mode=deep 的旧 API 继续可用；未指定 mode 的旧 deep 会话后续提问按 basic 执行。界面把旧 deep 结果标为“基础检索 · 已扩展”，不伪造该条记录不存在的基础结果。旧会话仅显示一次合并提示。

数据库 v17→v18 只增加可空的 turns.expansion_json，不改写旧数据。新库及旧库启动初始化均支持；重启后端以加载接口并执行迁移。会话导出、导入和刷新保留扩展结果。普通问答 PATCH 不会覆盖 expansion。

系统日志记录 operation、mode、session、turn、outcome；扩展保存失败有异常详情。没有改动模型、提示词、工具、AI约束策略或预算设置。

## 验证

隔离临时数据目录中的 tests/test_search_expansion.py 覆盖旧模式解析、扩展保存及导出导入、错误目标、撤销权限、成功空结果、失败保留、取消和重复请求、迁移保留原数据。结合检索模式、元数据库和账号权限回归，以及前端生产构建。

## 扩展失败及展示修正

扩展结果区域可整体折叠，新完成的扩展自动展开。扩展成功后，基础过程移到默认收起的基础结果区域；过程展示仍遵守用户设置。历史 deep 结果同样支持折叠。

权限检查使用独立的两线程执行器并保留请求上下文。超过5秒记录慢检查，并等待同一次检查最多额外10秒；没有通过检查的内容不会发布。错误日志关联问答、操作、阶段和原因。检索取消后回收排队任务并接收后台线程的迟到异常。

ONNX模型初始化加锁，内部计算线程限制为2，跨算子线程为1，关闭线程空转，以减少与其他请求争抢CPU。仍在同一进程中，并非硬资源隔离；重排耗时可能变化，需要部署后观察冷启动。模型和评分规则保持不变。
