# 知识库工具使用说明与边界

更新日期：2026-09-23。本文对应本次 1—8 项工具修复。工具向 AI 提供知识库访问能力；不新增答案核验、研究顺序或业务结论规则。运行时说明直接位于 `src/qa/knowledge_tools.py` 的 `TOOLS`，由协议适配器发送给模型。

## 当前接口

六个原有知识库工具保留：get_kb_overview、list_documents、search_knowledge、search_document、get_document_outline、read_document。新增四个单一用途入口：

| 工具 | 必填参数 | 作用 |
|---|---|---|
| search_scope | scope_ref、query | 搜索目录返回的完整章节、对象或工作表 |
| get_object_members | scope_ref | 查看对象成员目录，offset 续页 |
| continue_search | cursor | 使用 next_cursor 继续固定搜索快照 |
| read_table_rows | scope_ref、row_start、row_end | 读取工作表原始行区间，含首尾行 |

加上已有可选记录工具，默认共 11 个；存在当前会话历史时加入两个历史工具，共 13 个。工具数量增加用于减少单个接口的参数组合，不规定调用次数或顺序。

`search_document` 面向模型的参数不再含 section/object_id/sheet；`get_document_outline` 不再含 object_id。旧形状仅保留内部兼容校验，不在当前工具定义中展示。查对象用目录 query，查成员直接使用该对象 scope_ref。

## 阅读入口与范围入口

`read_ref` 代表阅读位置，`scope_ref` 代表完整搜索范围，`next_cursor` 代表某一次搜索的固定结果快照。三者不可互换，均属于本轮请求，不接收模型拼接的编号。

目录返回：文档 scope_ref、每个章节 scope_ref、每个对象 scope_ref，以及工作表 sheets 中的 scope_ref。工作表列表来自当前目录页，更多章节可继续翻页。范围绑定文档哈希和索引产物，同内容重建也使旧入口失效。不存在的范围返回错误，不忽略参数、不自动扩大范围。

示例顺序仅说明参数来源，不是强制研究步骤：

```json
{"document_id":15,"query":"MDSnapshot"}
```

这是 get_document_outline 的示例。取得 objects 中的 scope_ref 后，可以直接 search_scope：

```json
{"scope_ref":"<objects 返回的范围>","query":"num_bid_orders","match_mode":"identifier"}
```

也可以直接使用对象 read_ref 阅读，或者 get_object_members 查看成员。无需同时传递对象名、对象编号、章节号。

## 搜索覆盖和排序

新版索引可用时，文档 exact/identifier 直接扫描已解析原文，不依赖旧向量片段；当前知识库全部就绪文档均有新版索引时，全库精确搜索也走该路径。混合新旧索引知识库仍保留旧全库检索兼容路径，并标明覆盖来源。

范围内 exact/identifier 同样直接搜索原文，跨旧片段边界的内容和无向量片段的已索引文本也能命中。重复文本在不同位置保留独立匹配和引用。

范围内 keyword/related 基于原文窗口排序。semantic/hybrid 使用已有向量片段，按 20、80、200 个候选有界扩展后映射到范围，保留语义顺序或融合分数；仅语义命中的结果不会被关键词过滤掉。存在候选池和源片段精确定位限制，coverage.semantic 明示不保证穷尽。语义服务失败记录类型和关键词回退。范围窗口不是新的持久化向量索引。

移除旧文档相关搜索中“同章节通常只保留两条”和忽略空白/竖线的文本去重。仅合并相同来源位置/编号的确定重复，不按语义相似删除内容。移除写死的市场词组警告及排序优先级，返回真实章节标签。

## 固定分页与容量

搜索返回 next_cursor 后，continue_search 读取同一候选快照，不重新召回改变顺序。文档更新、删除或规范原文索引重建后，相关快照失效。旧 offset 调用也在请求内复用已保存的同查询快照；模型优先使用游标入口。

原文搜索最多保存 1,500 个候选、180 万正文字符，扫描上限 5,000 万字符；达到上限明确标记 scan_complete=false 和 capacity_limit_reached。每页最多 8 条。语义候选池完成不表示全库穷尽。

请求内最多 12 个搜索快照，合计约 800 万 JSON 字符；回收后游标明确返回失效。旧检索快照另限制 1,500 个候选、约 250 万 JSON 字符并报告截断。容量用于控制内存，不选择业务结论。模型可自行选择其他查询或更小范围。

## Excel 原始区域阅读

从目录 sheets 获取工作表 scope_ref，再传原始 row_start/row_end，不再手写工作表筛选条件。返回：

- 已读取原始行号、以原始列号为键的值及对应原文引用。
- 相关合并范围及其锚点原始内容，必要时跨解析分段读取锚点。
- 展示首行单独标注，business_header_identified=false，不声称自动识别业务表头。
- 实际返回范围、next_range、previous_range、following_range；超大行提供 pending_row.read_ref。

单次最多 40 个原始行号窗口，正文/单元格内容和序列化响应有独立大小保护。只展示已读取的值，不填充空白，不根据合并关系推导字段含义。已有格式 1 索引可复用，不需向量重算或批量重建。缺少行坐标时返回明确错误。

## 一致性与工具中立性

阅读进度比较加入索引产物和坐标体系，不把旧片段、新原文的同号章节当作相同坐标。对象声明来自同一个索引对象。新范围、游标和表格操作每次校验权限、版本及实际打开的索引；缓存不能绕过失效检查。正文相同但位置不同的命中不合并引用。

工具超时或容量不足只描述错误、读取状态和已返回资料是否有效，不指挥 AI 转入作答。不会增加答案审查、改变约束档位、默认轮次或模型配置。已有请求预算和传输恢复策略未修改。

## 性能和日志

新增阶段耗时：片段读取、文档加载、关键词排序/查询、向量化、向量查询、原文扫描、原文定位、结果序列化；复合检索沿用 TraceCollector 阶段计时。工具返回 tool_metrics，系统日志记录阶段毫秒值。嵌套阶段不可直接求和当作总耗时。

文档片段缓存仅存在本轮请求，绑定文档版本和片段 ID 列表，最多 4 篇、约 400 万正文字符；不跨用户共享。工具工作线程仍在隔离的请求状态内执行，超时不发布迟到的状态。

实际 HTTP 请求诊断记录工具定义 SHA256、必填/可选参数名、strict 状态和类型/nullable 信息。Chat、Responses、Anthropic 格式均支持；不记录 schema 描述、默认值、枚举或用户正文。用于核对代理前的定义，不假称已经知道代理内部如何转换。

## 验收范围

验证定位、分页、重复位置、权限/版本失效、语义独有结果保留、Excel 坐标和合并锚点及日志隐私。不用预设业务答案作为通过条件。没有调用付费模型、修改生产索引或重启服务。

验证结果：全量后端回归 590 项通过。使用已有不可变文档索引做只读调用核对，MDSnapshot 范围搜索命中并读全对象；Excel 工作表范围搜索与原始行区间读取成功。没有发起新的模型请求，尚未评价改动后的真实模型答案稳定性。
