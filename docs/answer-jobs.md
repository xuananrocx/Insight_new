# 会话后台生成与刷新恢复

## 行为

新前端把已保存的问题交给后台任务；刷新、断网、关闭页面仅断开订阅，服务器继续执行。返回会话时读取最后一轮任务和完整快照，不重复提交生成请求。停止按钮使用独立停止接口；删除会话或问题先停止任务，再删除数据。切换知识库继续沿用已有约束：存在问答时须新建会话。

服务器重启不自动重跑模型。正常关闭保存当前内容，启动时将异常退出遗留任务标为中断，保留最近一次检查点。用户自行新建提问重试。后台任务不会跨进程迁移。

## 实现与接口

- `src/qa/answer_jobs.py` 复用 `_sse_events`、模型选择上下文、工具链和权限检查，独立协程消费原事件流。
- `POST /api/v1/qa/jobs`：会话/问题作为幂等标识，正文摘要用于拒绝同标识不同请求。已有任务（包括已完成）不重复生成。停止请求先于创建到达时记录取消意图，防止迟到创建启动模型。
- `GET /api/v1/qa/jobs/{session_id}`：发现会话任务；`GET /api/v1/qa/jobs/{session_id}/{turn_id}`：返回带 revision 的完整快照。前端每秒获取一次、按版本替换内容，不拼接重复 token；断线重试只读快照。创建响应丢失时重试同一幂等创建。
- `POST /api/v1/qa/jobs/{session_id}/{turn_id}/stop`：显式停止。只有会话所有者可操作；停止不要求仍有知识库权限，便于撤权后结束任务。
- 创建/读取校验会话所有权、知识库权限和归属；执行中即使模型沉默也定期检查权限。原问答链路继续检查 API 使用权限及工具访问权限。
- 每秒最多保存一次变化快照，结束时立即保存；SQLite 检查点与对应回答在同一事务写入，取消须等待进行中的写入完成，防止旧检查点覆盖最终结果。
- 服务端独占已纳入任务管理的回答内容写入，旧客户端不能 PATCH 覆盖它；点赞仍可更新。旧问答、扩展检索和原 SSE 接口保留。
- 完成后任务表只保留轻量状态、幂等摘要和时间，回答、引用、阶段从现有 turns 表恢复。删除会话/问题同步清理任务记录，启动清理无对应问题的孤立记录。不保存密钥或请求历史。

## 配置与边界

沿用系统设置的“问答生成”区域：

| 配置 | 默认 | 范围 |
| --- | --- | --- |
| `qa.ai_generation.job_timeout_seconds` | 3600 秒 | 30–86400 秒 |
| `qa.ai_generation.job_max_concurrent` | 4 | 1–64 |

总时限覆盖查阅和作答，单次工具与模型网络超时仍独立生效。全站达到并发上限立即返回提示，不排队；同会话同时只允许一个任务。新设置对新任务生效，旧客户端保存不覆盖未提交字段。

第一版只支持仓库现有的单 worker 部署，不支持多个 worker/多台机器执行同一数据目录。没有事件日志无限增长问题；回答另有 400 万字符的防失控上限。页面每秒更新，超大回答的完整快照会增加网络开销，后续可在相同 revision 协议上增加增量传输。终端任务没有自动付费续跑能力。

## 数据变更、备份与回退

新增 `answer_jobs` 表，不重写历史回答或修改原表字段。启动时创建表并恢复状态。实际加载到本地前，先用 SQLite online backup 创建带时间戳的独立备份，再重启；不要仅复制 WAL 模式下的主数据库文件。

回退先停止活动任务并正常关闭服务，再同时回退前后端。旧代码忽略新表，原 turns 中的回答仍可读；无需删除任务表或恢复整个数据库。不要在正在执行任务时只回退前端，以免旧页面无法显式停止后台任务。

## 验证

隔离目录测试覆盖：无订阅继续生成、新 HTTP 客户端读取恢复、幂等创建、同标识冲突、停止先于创建、停止清理真实 SSE 生产者、超时、运行中撤权、真实账号越权拒绝、并发限制、会话删除、启动中断恢复、服务端写入保护、引用及阶段恢复、配置持久化。前端测试覆盖响应丢失重试、仅 GET 恢复、权限错误不重试及断连不等于停止。

本地人工验收：发送一条回答较长的问题，输出部分内容后刷新；确认没有重复气泡/重复文字，原回答继续输出。随后分别验证停止、切到另一会话再返回、断网后恢复和关闭页面再打开。重启服务的中断场景已用隔离测试验证，无需为了验收中断真实任务。未修改 176/224，未提交或推送。
