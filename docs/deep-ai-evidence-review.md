# AI约束策略（当前）

设置里的三档策略替代“仅依据知识库回答”。请求通过 deep_ai_options.constraint_strategy 传递 evidence / balanced / exploratory；未传时兼容 strict_knowledge（true 对应资料优先，false 对应综合分析）。显式策略优先，非法策略拒绝，不叠加旧开关。前端沿用按账号隔离的本地设置，不承诺跨设备同步。

ai_policy.py 统一共同底线、唯一当前策略及阶段任务。研究和作答都使用同一策略。工具保留客观原文、读取范围、原始问题及剩余轮数，删除重复行为规则、目录指挥及最终字段指导。研究记录未解决项保留在资料中，但不再覆盖模型正常结束原因。调用及容量保护仍保留。

系统日志记录 strategy、prompt_version、context_mode；当前上下文重组保持不变，未新增总结或核验调用。本文后续内容为历史记录，以本节为准。

# 当前作答策略

取消第三阶段的末尾模型核验流程，正文生成时实时流式发送，不再暂存整段等待复核。旧配置 semantic_verification_enabled 不再生效；历史核验调用日志保留用于排查。

研究记录工具按需使用，移除每次工具返回的重复核对指令。允许模型自主寻找能改变判断的资料、自主结束查阅，并优先给出可用判断；仅追问影响结论且工具无法获得的关键条件。知识库事实引用原文，通用知识及合理推断在关键位置说明边界，不要求逐句标签或固定模板。显式严格知识库模式仍尊重用户选择。

保留原文分页、引用校验、版本及权限检查、上下文容量保护和会话记忆。最终作答资料重组暂时保留，避免同时改变过多因素；历史及研究记录不作为独立事实依据。日志记录 streaming=true、post_verification=false 和 strict 状态。

# 深度 AI 证据链改造

## 第一阶段实现

- 原始问题由请求绑定，搜索词改写不会替代它。工具输出明确要求结合会话最新条件核对来源；不把用户陈述当成已验证事实。
- 搜索节选和章节阅读标记不同坐标基准、起止范围、截断、容量截断及章节完整性。搜索的 `read_hint` 用于打开章节；阅读的 `next_offset` 用于精确续读。分页保留原始空白。
- 指定文档检索与章节读取共用拼接坐标，重叠范围只计一次证据字符预算。相同文件、版本、章节的相同片段复用引用；不同来源和版本保持独立。尚未定位到章节坐标的全库搜索片段采用保守计数。
- 表格续读可返回章节首个可识别 Markdown 表头作为辅助背景，并明确提示多表章节不能自动套用。代码或表格被分页切开时提示继续阅读，不声称已恢复完整语义。
- 查阅进展分别统计新增证据、目录导航、历史及重复项；片段顺序变化和引用编号变化不算新增证据。统计表示新材料，不是语义问题已解决。
- 有限和不限轮数都收到原问题核对提示；临近轮数上限仅额外提示剩余资源。日志区分模型主动停止、轮数、时间、工具次数、证据容量、上下文容量、无进展、重复调用及模型异常。
- 最终回答增加通用检查要求，覆盖遗漏条件、部分可答、冲突和推断。当前仍不是独立语义核验，不能标为答案质量已验证。

## 回归案例与验收

`tests/fixtures/deep_ai_quality_cases.json` 提供 12 个合成案例，包括必要事实和禁止断言。判定应核对含义，不要求逐字复现 `must_include`，也不能用字符串匹配替代人工证据核对。

自动化测试验证分页、坐标预算、来源隔离、原问题传递、表头和进展统计；现有权限、取消、重试、协议和历史测试继续保留。真实模型质量评测另行运行，不能把模拟模型的流程测试当作质量提升证据。运行真实评测时固定模型、数据和配置，记录答案、来源、查阅路径、停止原因和耗时；选取少量高波动案例重复对比有限/不限轮数。

## 第二阶段实现

- 新增请求内工具 `record_evidence_review`，最多 8 个问题要点，分别记录可答、部分可答、冲突、未知及缺口。按稳定 ID 更新，不自动删除其他问题。简单问题可在查阅后一次记录，不要求先额外规划。
- 可答项必须引用已读原文，摘录必须逐字匹配对应证据；冲突项至少提供两条不同引用。非法更新整批拒绝，保留已有记录。这只验证出处，不证明模型判断正确。
- 后续工具结果携带未解决要点 ID。整理记录本身不计作新证据，也不能重置无进展或资源保护。若模型未记录要点，仍使用已读证据正常作答，并在日志中如实显示 0 项。
- 正式作答重建独立的消息列表：保留原始问题、近期会话、摘要/偏好、已读取历史及原文依据；排除本轮目录、重复工具交互、早期回答草稿和推理协议项。查阅期间的 Chat / Responses / Anthropic 协议记录保持完整，直到进入新的作答请求，不拆除单个工具消息。
- 要点结论明确标记为模型初步判断，正式回答仍需对照原文。输出继续流式展示，没有新增固定的每轮核验调用；记录要点可能占用额外查阅轮数，仍受用户配置限制。
- 按配置的上下文窗口估算作答预算，优先保留要点关联的完整证据；超限时只省略整条证据，记录省略编号，不静默截断事实。最终引用只允许使用实际进入作答资料的编号。记录和历史本身超限时明确报错，避免丢失用户纠正。
- 同一文件、版本、章节的完全相同原文在作答请求中仅传一次，保留引用别名及各自读取范围；不同来源不合并。证据容量省略会标为部分完成。要点记录仍有缺口或冲突时，停止原因与可回答状态分别记录，不把模型主动停止当成全部问题已解决。
- 系统日志新增作答重组统计，AI 调用日志保留问题要点工具请求及结果；页面 trace 显示问题要点和作答依据准备情况。工具摘录校验与独立语义核验保持区分。

## 第三阶段实现

- `qa.deep_ai.semantic_verification_enabled` 缺省为 true。对未记录要点、有缺口/冲突、多要点、多文档、依据不完整或因预算停止的请求启用独立模型核验。单点、同一文档、已用完整章节支持且正常结束的请求可直接流式回答。该策略是保守启发式，不能识别所有语义风险。
- 触发核验后暂存回答，页面显示生成/核验进度；核验完成后一次展示正文，避免先展示后撤回错误答案。用户可在生成和核验期间停止。
- 核验使用同一授权 API 的独立请求，重新设置系统提示及消息，只提供问题、历史背景、原文和草稿，不提供查阅模型的要点判断作为依据。不再调用知识库工具，不循环修改或无限复核。
- 核验至多 45 秒，受本次总时长剩余额度限制。启用总时长限制时从回答阶段为核验留出最多 30 秒。上下文预算预留草稿/核验空间；实际核验输入仍再检查一次，超限不静默裁剪关键依据。
- 返回结构化通过/问题/修正结果。可用修正必须使用当前允许的引用；未通过且没有可用修正时不展示被否定的草稿，改为提供已读原文。超时、网络失败或无效核验响应保留带“未完成复核”提示的草稿并标为部分完成；生成本身不完整时不标为已核验。
- 权限撤销和用户取消不会降级成可展示草稿，缓冲正文不会通过 token 或 error.partial 泄露。发布正文前继续进行原有文件版本与权限检查。
- AI 调用日志新增 `deep_ai_verify`，界面显示“深度 AI · 语义核验”，沿用日志开关和账号隔离。系统日志记录触发原因、完成状态、问题数量及降级异常类型。
- `model_checked` / `model_revised` 仅表示完成自动模型复核，不是事实正确性保证。核验使用同一模型，仍可能漏判或误判；一次修正后不额外做第二次核验，避免费用和延迟无界增长。

2026-09-22 第二阶段抽查：使用真实 Responses API 和隔离的合成文档，版本差异、部分可答、历史纠正三个案例均成功记录要点并完成作答；答案分别保留热更新限制、未编造内存数值、采用最新 Linux 环境。检索使用固定合成文档的关键词适配器，不是生产知识库端到端检索评测，也不是多次重复稳定性实验。

第三阶段真实 API 抽查：版本差异与部分可答案例完成核验，历史纠正的完整单点依据跳过额外核验；三例答案符合合成资料。另向核验请求提供刻意错误的“所有配置均可热更新、监听地址无需重启”草稿，模型指出两处无依据结论并修正为“仅规则文件支持，监听地址变更仍须重启”，保留有效引用。该抽查验证通过与修正两条真实协议路径，不代表复杂生产资料的整体质量保证。失败、无效修正、超时、取消和权限撤销由隔离自动化测试覆盖。

当前没有重建旧索引、没有改变权限体系、没有新增每轮 AI 调用。PDF 重复解析、复杂合并表头、跨章节代码结构等源头问题仍需专门的解析改造，不能由读取提示完全解决。总时长仍从代理查阅开始计时，不包括前置会话准备，这一行为待统一请求预算时处理。
