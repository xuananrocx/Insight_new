# 新服务器部署前问题清单

本次仅本地修复并提交，不连接生产数据、不创建服务器用户、不部署。

## 已修复，随新构建交付

1. HTTP 内网页面提问失败：UUID 优先原生实现，否则使用 crypto.getRandomValues 生成 v4 UUID。旧服务器修改静态文件的临时补丁已转为源码。
2. Windows/Linux 知识库包路径不兼容：统一 ZIP 路径并检查路径穿越、重复路径、缺失文档、文件大小/hash、分块引用、重复 ID 和向量有效性。失败在创建新库之前返回。
3. 不同章节 chunk_index 相同导致导入 ID 冲突：新库 ID 与原始分块 ID 共同生成唯一 ID，保留章节内序号和文件 hash。不丢弃正文。
4. 摘要分块文档关联丢失：通过正文中的原 file_id 映射恢复摘要关联；无法唯一关联时明确拒绝，不生成孤立摘要。
5. 导出文件缺失或内容已变化仍静默成功：导出前验证，并对生成的包复核。错误包不会作为成功结果返回。
6. 概念/摘要/全局概览未包含在导出包：新包添加可选 derived_metadata，重映射文件和概念 ID。旧包仍可导入，不虚构缺失元数据；过期概览不会被标成新鲜快照。
7. 关键词索引写入异常被忽略：导入失败执行清理，按知识库收集已落盘关键词记录，覆盖摘要和尚未登记到文档的批次。
8. 导入后启动独立阅读索引任务，使用现有任务状态和手动重建入口。阅读索引建设失败不销毁已经完成的文档/向量导入，日志明确提示重试。
9. 模型切换加载失败：恢复旧模型名、模型实例及维度；前端显示错误。若 config.local.yaml 已覆盖模型选择，保存到实际生效层并原子替换文件。
10. 可选 API 绑定失败丢失原始错误：请求内保留原始 HTTP 状态和原因，实际 AI 调用时透传，不绕过用户授权。
11. 同步调用空文本误记成功：拒绝空响应；日志模型名改取实际 chat_model。Anthropic-arch 合并全部 text block，返回用量写入现有 token 字段；结束原因/用量记录到系统日志，max_tokens 截断明确报错。流式工具流程保持不变。

## 未确认根因，暂不修改

- 新导入立即显示“任务历时 5.8 min / 当前步骤 5.8 min”：需核对任务创建/阶段时间、浏览器与服务器时钟、恢复后台任务逻辑。没有直接按时区差硬修。
- 旧服务器 8088 和 8090 同时 500、SSH 异常：当时无法登入读取故障日志，不能确认磁盘、权限或服务原因。
- GLM 摘要不完整 JSON、空文本、超时：现已增加明确错误和诊断，但历史响应缺 stop_reason/usage，不能确认全部由 token 上限引起。不直接放大 600/1500 的预算，不声称生成质量已修复。
- 原始 409 API 选择错误的触发条件：保留准确错误已修复，但历史配置与权限是否变化仍需真实请求验证。
- 模型切换成功但配置文件写入失败仍只在日志提示：现有行为保留，后续应考虑事务式配置持久化和 UI 提示。

## 部署准备项（不是本轮业务代码修复）

- 新服务器调研：4 vCPU、约 4GB RAM、40GB 根盘/约 35GB 可用、CentOS 7，未装 Docker/Nginx。不得照搬旧服务器 8GB 容器限制。
- 旧站点上传临时目录权限问题已通过单独目录解决；新部署必须按实际 Nginx worker 身份建立目录，不使用 777。
- 离线模型需要完整权重/配置/分词器及正确缓存路径；旧机已补齐不代表新机具备。
- 容器域名解析及 API 连通性逐环境核验。plan.ai.archforce.cn 解析到内网地址，不能将域名映射等同于公网机器可访问内网 API。
- 启动脚本、日志轮转、健康检查、磁盘阈值、重启恢复和备份应随最终部署方案验证。旧静态补丁不能依赖容器可写层长期保存。
