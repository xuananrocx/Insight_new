## 第一优先级：上下文、模型能力与实际预算

建议位置：系统设置 → AI 运行配置 → 会话上下文与预算。编辑沿用 `system.edit`，查看沿用 `system.view`，不增加普通用户的系统配置权限。

| 项目 | 当前来源与范围 | 当前入口 | 后续安排 |
| --- | --- | --- | --- |
| 全局上下文窗口 | `qa.conversation_context.context_window_tokens`；默认 65,536，16,384–262,144 | 无页面入口 | 增加管理员配置，作为模型容量未知时的兜底 |
| 近期历史预算 | 同节 `history_tokens`；默认 8,000，1,000–24,000 | 无页面入口 | 放入高级设置，展示与窗口/输出预算的关系 |
| 会话记忆摘要输入预算 | 同节 `summary_input_tokens`；默认 10,000，2,000–20,000 | 无页面入口 | 明确是会话记忆摘要，与文档摘要分开 |
| 会话记忆摘要输出上限 | 同节 `summary_tokens`；默认 2,400，500–4,000 | 无页面入口 | 同上 |
| 单模型上下文容量和最大输出 | API 模型配置 `context_tokens` / `output_tokens` | 已有 API 模型编辑入口 | 接入问答预算；当前摘要策略已读取，深度问答的窗口计算尚未使用 |
| 实际生效预算与来源 | 当前主要依靠 trace 和系统日志 | 部分上下文信息可展开查看 | 展示系统配置、模型约束、输入估算、实际输出上限及缩减原因 |

建议统一优先级：所选模型的已配置容量优先，全局窗口为未知容量的兜底；系统输出上限和模型最大输出共同限制实际输出。模型能力字段是管理员填写的约束，不能宣称自动检测或认证。

还需调整预算策略，而非仅新增表单：

- 提前为最终作答预留空间，覆盖推理模型生成需要；当前查阅停止条件涉及 `8192 + 4096`，最终作答另留 `3000`，这些是代码策略常量。
- 不能仅因完整查阅上下文还能容纳约 1,024 输出 tokens，就始终优先沿用完整上下文；应结合目标作答预算决定是否压缩资料。
- 增强 AI 当前输出上限还受窗口一半限制；统一展示该约束，避免配置值与实际值不一致却不解释。
- 输出截断提示区分：系统输出封顶、模型输出能力、上下文剩余不足；不再一律引导调大输出上限。
- 生效方式优先采用受控接口保存并更新内存，新请求生效；明确运行中任务是否沿用原快照，避免管理员保存后误以为全部即时切换。

## 已有入口，避免重复建设

- 系统设置 → AI 运行配置：连接检测/正式请求超时、联网总开关、问答输出上限、作答时长、工具超时、深度 AI 原文字符预算、问答任务时长及并发。
- 文档摘要运行配置：`SummaryPolicy` 字段已通过专用接口和组件提供；不要与会话记忆摘要混用。
- API 模型编辑：上下文容量和最大输出；需要补齐问答使用链路，而非另造重复字段。
- 深度 AI 查阅轮数、总时长开关及限制，检索深度：已有个人/对话入口；系统默认与个人选择的优先级应明确。
- AI 调用日志的记录项和保留天数：已有独立管理入口。
- MCP：本地开发中的独立设置保持独立，不混入问答上下文设置。
