# MCP 面向 Agent 的质量优化执行方案

日期：2026-11-12。状态：方案，未修改运行代码或配置，未重启服务。

目标：提高外部 Agent 使用知识库后回答的准确性、完整性、引用可靠性和查阅效率。文档产出功能暂停。MCP 的直接消费者是 Agent 与模型；协议与返回结构以可推理、可执行、可恢复为准，不按面向人的页面或说明书设计。

## 1. 输入依据与证据边界

参考用户提供的下游报告 `insight-mcp-baseline-2026-11-12.md`，并核对当前 `src/mcp/`、`knowledge_tools.py`、`canonical_search.py`。原报告保留在用户本机，不复制其中的私有知识库标识或原文进仓库。

报告是下游实测记录，尚未在本轮独立重放；耗时和召回结论适用于当时的数据、配置和查询，不能泛化到全部模型、客户端或知识库。

| 报告发现 | 源码核对及结论 | 纳入方案 |
| --- | --- | --- |
| 中文排障问题未召回英文固件脚本，语义结果大量为证券记录 | 接受未召回现象；跨语言能力、索引覆盖、候选过滤和排序均可能影响，尚不能断言单一根因 | 路径诊断、多信号召回、有限文档多样性、明确的语言补查入口 |
| 大 XML 的重复候选淹没小文档 | 代码存在有限候选池；精确扫描按文档顺序进行并共享上限，有被前序大文档耗尽的机制 | 重叠片段合并、扫描配额、区分结果翻页和继续扫描 |
| exact 相邻命中片段几乎相同 | 当前仅按坐标元组去重，不合并重叠窗口 | 在同文档同版本同节内合并，并保留各命中坐标 |
| 1500 条命中后仅扫描部分文档 | MAX_RESULTS=1500、总片段容量与扫描字符限制可中止整个扫描；continue_search 只翻已有快照 | 显式未扫范围，有限扫描续接，不能把快照翻完称为全库查完 |
| search_scope 对单节大文档不提速 | scope 是语义范围，单节可能仍覆盖整份大文件 | 显示范围规模；优化读取和定位，不承诺 scope 必然更快 |
| related 对短英文脚本返回空 | 该路径主要按关键词排名；no_match 不能证明索引不存在或文档无答案 | 标明匹配方式和索引状态，提供有界原文阅读/语义补查入口 |
| 8–18 秒耗时未归因 | 现有 tool_metrics 不覆盖全链路；阶段可能嵌套，不能简单相加认定遗漏时长 | 分层计时、排队/查询/定位/序列化/引用存储分类 |
| 并发约 2，四请求部分被拒 | 报告时默认并发为 1，可配置 1–4；后续已支持正整数自定义，无固定数值上限 | 读取实际配置确认；繁忙提示重试，仍不积压队列 |
| 概览“含摘要生成” | overview 读取已存摘要并核对新鲜度，不触发聊天模型生成 | 纠正文档理解；保留背景摘要非证据标记 |
| 服务版本 1.30.0 | 当前 SDK 版本为 1.30.0，不能当作 Insight 应用版本 | 分开应用版本、MCP 合约版本和 SDK 诊断版本 |
| resources/prompts 不支持 | 当前 tools 足以完成查询；缺少这两类能力本身不是质量缺陷 | 暂不为功能数量新增 |

## 2. 架构和范围

- 保持独立网关、MCP 专用设置、个人令牌与现有资源权限。
- 服务端提供资料、定位、覆盖和可执行的查询入口，不管理 Agent 的任务计划、完整对话、推理、最终回答或累计证据审查。
- 不调用第二个聊天模型翻译查询、生成查询策略或总结证据。模型扩词与跨语言改写由外部 Agent 决定。
- 首先修改 MCP 合约和适配层。共享查询算法确需修复时，提取公共能力或以显式策略传入，网页问答保持原默认行为并单独回归。
- 不按文件大小强行给无关小文档保留最终结果席位；多样性须以相关性为基础。
- 不把改 embedding 模型作为默认措施：更换意味着向量兼容与重建，须另立方案。
- 原 11 项工具保持名称；新增参数可选、原语义不偷换，旧客户端可以继续调用。

## 3. 工作包 A：Agent 可理解的工具合约

目标：模型能正确选择工具、构造参数并理解结果边界。

1. 建立 MCP 专用描述层，复用执行能力，不再仅字符串替换内部文案。
2. 每个工具描述只包含适用意图、必要前置、关键参数区别和后续入口；公共约束集中在服务器 instructions。关键限制仍保留在对应工具，避免依赖客户端一定注入 instructions。
3. 明确 exact 为字面子串、identifier 为标识符边界；keyword/related 的具体行为必须与路径一致。semantic 不保证穷尽；hybrid 说明实际融合和降级。
4. 参数引用说明明确类型与来源：read_ref、scope_ref、cursor 不互换；document_id 必须来自真实返回。
5. 增加可选概览 query，按提供查询选择目录；未提供时标记 sample_catalog，不称按问题排序。
6. 概览与文档列表提供可用性摘要：处理状态、阅读/语义索引可用性、是否支持对象或表格导航。优先使用已知元数据，不额外全库扫描。
7. 建立返回合约模型和 outputSchema，结构化结果与文本兼容输出保持语义一致；错误结构也纳入定义。实测客户端是否重复注入内容后再决定精简方式。
8. 应用版本、结果合约版本单独标识，不能误报 SDK 版本为产品版本。

涉及：src/mcp/tools.py、gateway.py；可新增 contracts.py / descriptions.py。检验：schema 合法、参数兼容、只读属性准确、概览排序描述与行为一致。

## 4. 工作包 B：证据结果与稳定来源

目标：Agent 可跨调用合并来源、去重和正确引用。

在保留现有字段的兼容期增加：

- contract_version、request_id：标识合约和本次调用。
- outcome：ok / partial / no_match / error；no_match 只表示当前查询范围及匹配方式未命中。
- scope：实际知识库、文档/结构范围、匹配方式、实际检索路径和降级情况。
- evidence：原文与来源；不以生成摘要代替原文。
- coverage：扫描完整性、解析完整性、候选限制、当前返回截断、未扫描范围。
- continuations：已验证的下一步工具名和完整参数，区分结果翻页、阅读续页与扫描续接。
- diagnostics：紧凑计数；详细阶段性能进入日志或显式诊断模式，减少常规模型输入噪声。

来源设计：

- source_id 标识知识库+文档+内容版本；evidence_id 再包含阅读索引版本、坐标类型和原文范围。
- 同一来源不同范围可用 source_id 关联；同一精确范围可用 evidence_id 去重。重建或更新后不能错误沿用旧坐标身份。
- 旧 citation 仍保留，并明确只在本次调用有效；Agent 可基于稳定 ID 重新编号。
- read_ref 仍是短期带权限检查的导航入口，稳定 ID 不作为绕过鉴权的读取凭据。
- 没有可靠坐标的旧检索候选明确 location_unverified；必要时使用内容指纹作去重辅助，不能伪造精确定位。
- 为保留旧字段而增加的重复内容必须计入返回上限；稳定字段不能无限堆叠。

## 5. 工作包 C：覆盖语义与继续查阅

目标：阻止“翻完当前候选=查全知识库”“局部无命中=事实不存在”等误读。

1. 分别表达 page_complete、scan_complete、candidate_limited、parse_completeness、documents_requested/started/completed。未确定状态用 unknown，不推断为 true。
2. 原文读取返回本次准确区间与对象总范围；跨调用累计覆盖由 Agent 计算。
3. 保留快速的 continue_search 快照翻页；继续扫描使用显式独立入口语义，例如可选的 scan_cursor，不能让原结果 cursor 悄悄重扫或变序。
4. 已完成快照和待扫描状态分开，均绑定令牌、知识库、查询、版本及有效期，并沿用空间上限。
5. 先消费当前结果还是继续扫描，由 Agent 根据任务决定；服务端只提供事实性入口，不宣称“证据已充分”。
6. 有限扫描续接必须携带文档/章节/字符进度，而不是增大 offset 后重头再扫；版本变动时明确失效。
7. 游标接续边界保留未输出命中和重叠上下文，不跳过或重复关键命中；不能跨权限范围恢复扫描。

## 6. 工作包 D：超限分页与错误恢复

目标：工具遇到限制时仍能返回可用资料和可操作的恢复路径。

1. 按完整序列化 envelope 控制字符/字节预算，取消固定“正文只分配一半”的唯一策略；正文与元数据共同计费并保留边距。
2. 在生成阶段按证据条目或合法原文边界分页，避免先产生大量数据再整体 413。
3. 单条证据超限时返回可容纳片段、准确区间与续读入口。不能返回空页面加无法推进的同一游标。
4. 目录、知识库列表、对象成员也须有受控分页；稳定排序、明确 next_offset 或 cursor。
5. 错误保留旧 error/message，同时增加 code、retryable、recovery。区分 busy、rate_limited、reference_expired、reference_invalid、document_changed、index_unavailable、invalid_arguments、timeout。
6. 不对无权访问者暴露“引用属于他人”等存在性细节；恢复入口只能使用调用者已获准的信息。
7. 对繁忙/限流提供退避建议。没有确定释放时间时 retry_after_ms 明确为建议，不能伪装精确承诺。
8. 返回 partial 中已有证据仍可用；SDK isError 与 outcome 的对应须明确，不能仅因任意 error 字段存在而掩盖成功取得的资料。

## 7. 工作包 E：下游报告补充的检索与效率问题

### E1. 精确匹配的重复片段和大文件偏置

- 仅在同文档同版本同节/范围内合并重叠或紧邻窗口，合并后保留 match_positions 和命中数量。
- 保留不同记录/对象的身份，不能按文本相似度把不同业务记录当成一条；窗口过大时继续分页。
- 第一轮采用受限的逐文档扫描配额和轮转，避免第一个大文档耗尽所有机会；剩余工作由扫描续接表达。
- 不承诺一次请求能穷尽千万字符文档；完整枚举需多次有界调用，且途中可取消。
- 区分原始命中数、合并证据数、已保存候选数、未知总数，不再让 matching_chunks 被误解为全库总命中。

### E2. 中文到英文、小文档漏召回

先定位再选择措施：

1. 核查目标文档的解析结果、当前 chunk、向量所属文档/版本、向量模型一致性与失效过滤；索引问题优先修复。
2. 比较中文 query、英文原词 query、文档内精确和文档内语义路径，区分语言差距、候选问题和排名问题。
3. 给 Agent 提供文件名/标题候选与文档可阅读入口；短脚本 no_match 时可读取有界原文，不做无声自动扩搜。
4. 在 MCP 搜索策略中引入原文、文件名/标题等独立检索信号和适度去重/来源多样性；候选扩大后再有界选择，不仅扩大返回条数。
5. 必要时增加可选 query_variants（少量、严格限长、共享总预算），接收 Agent 提供的英文关键词或同义词；不由服务端模型代写，不无限放大检索工作量。
6. 明确 variants 的模式约束：exact 仍分别保留每个字面查询及命中归属，不能把精确查询悄悄变成语义查询。
7. 不硬编码某个脚本名、知识库、中文词和答案。新增分词别名须可解释、可配置且可回退。

### E3. 双管线路径

- 第一轮统一返回语义、路径标记和降级解释，不直接删除 legacy 路径。
- 检查每种模式是否真正需要 chunk 检索、原文扫描或两者融合。阅读索引没有覆盖全部文档时保留可用降级。
- 同一版本原文作为定位依据；索引身份、解析缺口和候选映射必须可追踪。
- 待路径行为有回归保证后，再决定公共检索入口整合；不能仅为结构整洁而全量重建或改变网页默认搜索。

### E4. 耗时与并发

- 记录网关往返、主服务鉴权/限流、加载文档与索引、查询、定位、证据组装、引用存储、序列化等阶段。
- 使用包含/排他的清晰计时关系，嵌套阶段不重复累加；向模型返回紧凑统计，详细诊断使用 request_id 关联。
- 重点排查反复鉴权/索引读取、候选定位、数据库引用写入、相同查询重复 embedding；先测量再优化。
- 对已经拥有可信精确坐标的候选，评估直接构建阅读入口，避免为定位再遍历整份原文；必须核对版本、坐标和解析产物。
- 保持取消后正在运行的底层工作占用并发槽，防止假释放导致资源超卖。
- 优先改善 busy/rate_limited 恢复；只有测量证明需要时引入 MCP 独立、有容量和截止时间的短队列。入队取消、排队权限变化、账号公平性都要验证。
- 不直接增大默认并发；多人负载与本地 embedding 资源验证后再确定。

## 8. 实施顺序与提交拆分

| 顺序 | 交付 | 主要依赖及验收 |
| --- | --- | --- |
| 1 | MCP 合约、工具描述、概览修正、应用版本标识 | 原 11 工具调用兼容；已有客户端无需改必填参数 |
| 2 | 稳定来源、统一 coverage、continuations 和错误恢复 | 引用跨调用可关联、权限仍实时、错误能正确恢复 |
| 3 | 完整返回预算和各工具分页 | 无整次结果因超限白做；续页有进度且无资料丢失 |
| 4 | 全链路诊断、精确窗口合并、有限扫描续接 | 不因大文档无限占用；快照翻页速度不回退 |
| 5 | 基于定位结果修复召回/路径问题，选择性加入多信号与查询变体 | 相关性优先、不硬编码特定知识库；网页默认行为有回归保护 |
| 6 | 最后进行下游 Agent 回答效果评测与参数收敛 | 与原始基线比较；不以功能通过替代回答质量通过 |

每个工作包独立提交，协议字段以加法兼容为主。新增持久化状态优先复用有版本标记的 MCP 引用记录；确需 schema 迁移时另列迁移与回退计划后实施。

## 9. 验证放在什么阶段

遵从用户要求：正式回答效果对比放在全部优化完成后。现有下游报告直接作为起始基线，不先组织一轮新的大规模效果测试。

开发中仍执行功能和正确性检查：隔离 AMD_DATA_DIR、权限撤销、版本失效、分页推进、合并不丢命中、超限返回、取消和并发槽、旧参数兼容、结构化/文本返回一致、原网页问答回归。不得使用真实用户库执行修改测试。

最后复用报告 P1–P7，保持相同知识版本、客户端、模型、提示、模式和限额；记录环境差异。增加表格正向样本、版本冲突、真正无答案、跨页完整列举和长任务引用合并。资料复查使用只读调用，客户端凭据不进日志和仓库。

评测分层：

- 工具：必需来源是否召回、去重后有效证据密度、返回大小、首查/续页耗时、无效调用和恢复次数。
- Agent：关键事实覆盖、错误结论、无依据推断、引用位置正确性、对未查全/无答案的表述。
- 复杂题重复运行，区分偶然模型波动和稳定改善；不承诺固定准确率提升。
- semantic/hybrid 不能只以“包含一个目标文件”判成功，还须评估其他结果相关性和最终答案是否正确。
- 退化项必须记录，精确字段和 fast continuation 是现有优势，不能以改善自然语言检索为由牺牲。

## 10. 完成标准与回退

完成标准：六项质量目标有可核查的合约支撑；下游基线问题均有修复或明确诊断；最后效果对比说明收益、退化和剩余限制。

回退：MCP 专用策略可恢复到原行为；保留现有工具名和旧字段；合约升级产生的引用通过版本检查明确失效并要求重新搜索。网页共享算法改动单独提交、单独回退。实现和测试完成后，再按仓库规则确认本地服务重启；本方案不部署生产、不改 embedding 配置、不自动提交代码。
