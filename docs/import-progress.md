# 文件导入与 Excel 内存优化

- Excel 入库通过 `iter_xlsx_sections` 逐块解析并切片；兼容入口 `parse_xlsx` 仍返回完整文档，不用于入库大文件。
- 使用固定版本 openpyxl 3.1.5 的读取适配器，保留日期、布尔值、富文本和公式缓存值；不执行公式。
- 共享字符串使用临时 SQLite（1 MiB 页缓存和 128 条查询缓存）；每张工作表的稀疏行暂存磁盘。忽略格式单元格、纯空白行和全空列，保留有效列顺序及原始列名/行号。
- Markdown 按约 32 Ki 字符分块，重复表头以保留上下文；单行或表头特别大时块可能超限，不截断有效数据。正常、失败、取消和生成器关闭都会释放临时文件。
- 入库每批最多 32 个片段进行向量化和写入，及时释放向量；BM25 统一更新避免每批重建全库。切片文本、模型及检索索引自身仍占内存，不声称整个进程恒定占用。
- 在写入前记录片段 ID，中断重试可清理部分索引；只跳过已完成入库记录，pending/failed 重新处理。
- worker 全局串行并防止同任务重复启动。中断恢复重新排队 processing 文件，保留已完成文件；没有待处理文件时核对终态，避免永久显示运行中。
- SQLite schema 14 持久化阶段、阶段百分比和详情。SSE 先订阅再读取快照，前后台共用快照字段。暂停时点击“继续导入”，无需重传文件。
- 单文件显示阶段进度，多文件显示完成数。百分比仅表示可计数阶段的完成比例；未知比例使用不定进度，不再使用固定的 15/60/95%。
- 日志 `ingest phase` 记录阶段耗时；`ingest batches` 单列向量化与向量写入耗时。Excel 的 parsing 耗时包括随解析进行的切片。

## 验证

17 项后端测试覆盖恢复、重复启动、取消、快照、分批写入/中断、空白格式范围、共享字符串、日期、公式缓存与分块内容完整性；前端构建及浏览器后台切换、恢复重连、单文件展示和移动端溢出检查通过。

运行 `python -m scripts.benchmark_xlsx_memory` 可复现解析内存对比（只创建临时 Excel，不调用模型或访问应用数据库）。6000 行 × 8 列、约 1000 万字符样本，tracemalloc 测得旧解析峰值 61.73 MiB，流式消费峰值 1.16 MiB；耗时 32.58 / 34.12 秒（含内存追踪开销）。这是解析器 Python 分配峰值，不是应用 RSS、GPU 内存或全流程速度。


## 安全取消与发布（schema 15）

取消采用协作方式：cancelling → cleaning → cancelled；清理失败为 cleanup_failed，可再次点击“重试清理”。计算和同步 API 请求不会被强杀，返回后的检查点停止后续操作。独立进程强制中断不在本次实现内。

向量逐批暂存到应用数据目录 ingest-staging 的 JSONL 文件，SQLite ingest_runs 保存本次 ID 和提交状态。覆盖导入保留旧文件记录及索引，提交成功前不删除旧数据。最终发布使用检索锁保护，失败撤销新增索引，成功后切换文件元数据并删除旧索引。清理失败的未提交/已退役片段会被检索过滤，不会当成正常资料使用。启动会重试未完成清理，保留无法清理的日志供再次操作。

新文件取消会删除尚未入库的数据库记录；上传源文件保留。源文件在上传时已写入投喂目录，旧索引保护不等于备份旧源文件。正文已提交后取消摘要，保留正文，只停止后续摘要请求；已在执行的请求需等待返回。内存仍以一个批次的向量为上限，磁盘空间不足会中止新导入并保留原索引。

### CPU 小样本对比

同一离线缓存 bge-large-zh-v1.5 模型、16 段每段 700 字符的合成文本，每项预热后测一次。默认 14 线程、batch=16：25.847 s；4 线程、batch=8：55.884 s；8 线程、batch=8：38.893 s；4 线程、batch=16：54.246 s。此结果不足以认定最优参数，但没有支持降低线程数的证据，因此未改生产线程数、模型或批大小。测试未调用外部模型 API、未重建用户知识库。
