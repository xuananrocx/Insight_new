# MCP 相关性优化：范围、验证与限制

## 为什么不能复现“第二轮无噪音”

第二轮向量模型加载失败，结果来自关键词降级；第三轮恢复向量后暴露了中文问题与英文资料之间的召回偏差。目标是减少无关证据，同时保留其他领域、短答案和跨语言资料，而非屏蔽某个文件。

## 实现边界

修改集中在 MCP：`relevance.py`、`ranked_search.py`、独立配置和系统 MCP 设置。网页问答检索算法及共享 reranker 不改；exact / identifier 和 keyword 不新增重排。related / semantic / hybrid 使用原问题评估候选，Agent 提供的变体参与召回，不替代原问题作为评分目标。

1. 全库候选以外，最多对 8 个尚未进入候选且有 chunk 的文档定向查询，每份最多 4 条；先给小文档机会，不按具体文件名或格式判断相关性。该路径只在 MCP 相关性开关打开时启用。额外候选仍需评分，不当成相关证据自动输出。
2. 重排池默认 24 条（可设 4–40），按来源轮转选取。同文档相同文本不重复评估；不同文档相同文本保留来源。不保证跨边界或近似片段全部去重。
3. 本地 BGE reranker v2 m3 使用实际 logits 经一次 sigmoid 转换，评分不代表正确概率。单条候选也评分；直接评估正文，不拼接未经验证的文件名。每段最多 2500 字符，模型最多 512 tokens；不是全文评估。
4. 默认最低评分 0.10（可调整 0–1）。通过者按评分排列，limit 只代表最大条数，不要求凑满。该默认值经有限合成样本验证，不是通用准确率承诺。
5. 默认批次软预算 12 秒（可设 2–30），每批最多 4 条，批次前后检查取消与权限。不可中断在途 CPU 推理；冷加载也可能超过软预算。不会释放仍在运行的 MCP 并发槽。
6. `relevance` 明确 enabled、status、candidate_count、selected_count、scored_count、unassessed_count、accepted_count、threshold 及评分范围。预算耗尽后不把未评分候选混入已筛选结果。完全不可用时保留原候选并标记 unavailable / partial，不能声称过滤成功。未返回不等于全库不存在。
7. 不调用聊天模型、不自动翻译、不自动下载重排模型。读取 HF 配置缓存及标准用户缓存，未部署/加载失败时显式降级，失败冷却 60 秒。模型加载后常驻本进程，会增加内存占用；关闭开关停止后续推理，但不主动释放正在使用的模型。

## 设置、兼容与回退

系统设置 → MCP 接入新增独立相关性开关、候选数、软时间预算及最低评分。修改后保存生效，权限沿用 system.edit。新项保存到独立 app_state.mcp_retrieval_settings，原 mcp_settings 不增加旧版无法识别的字段；旧客户端省略新字段时保留既有偏好。无 schema 迁移、无索引重建、无模型切换。

旧数据未配置时默认启用本地相关性筛选；若模型未部署会显式降级，不发起下载。关闭开关恢复 MCP 融合候选路径。回退代码时旧版忽略独立配置键；升级产生的分页快照应重新查询，不承诺跨版本分页结果完全相同。

## 剩余限制与下游验收

上述短文集不能代替千万字符真实库或最终 Agent 回答质量。最多 8 份额外文档和 24 条重排候选仍可能漏召回；对超长 chunk 仅评分前段，后段可能包含答案。需 Agent 按提示提供查询变体、定位文档、读目录/原文继续查。评分阈值提高会增加漏召回风险，不应针对单题反复调高。

建议独立 Claude Code + GLM 复测时同时问固件、证券、无答案、跨版本和短答案问题，记录 relevance.status、实际路径、候选数量、原文引用与最终回答。既看过滤掉什么，也看遗漏了什么。并发配置未改变，重排有独立互斥避免同时加载；忙碌时会显式降级，未承诺多人同时推理吞吐。

## 2026-11-13：候选有效性与降级契约修复

本轮保持模型、512 token 输入上限、默认 24 候选及 0.10 阈值不变。候选覆盖判断与最终融合共用 `valid_candidates`：仅当前正文、正确文档归属和版本可以算作已覆盖；摘要、非当前片段及失效命中不再阻止补查。每次最多补查 8 个来源，每个来源先取 4 条，正文不足时最多扩大到 16 条一次；不会无限补查。`coverage.unprobed_sources` 明示未补查数量，`candidate_counts` 提供原始/有效/融合/返回候选计数。达到上限不表示全库无答案。

指定文档的词法查询通过可选 `allowed_ids` 在候选截断前限制当前文档片段。底层 BM25 默认参数行为不变，站内问答不启用这个范围参数；无数据库迁移。

重排尚未评分即失败时，保留 `status=partial`、`relevance.status=unavailable`，返回的线索移到 `unassessed_candidates`，`evidence=[]`。新列表沿用来源标识、读取引用、权限/版本绑定及无损输出分页；`relevance_status=unassessed` 表明只是定位线索。旧客户端只读 evidence 时会看到部分完成且无证据，应按 guidance 重试或读目录，不再把未评估线索误认作通过筛选的证据。已完成部分评分时只返回通过评估的片段，并注明未评估数量。

稳定原因码：`reranker_busy`、`reranker_cooling_down`、`reranker_not_deployed`、`invalid_reranker_output`、`reranker_failed`、`time_budget`。busy 建议稍后重试（1 秒只是建议，不保证模型空闲）。本轮保留非阻塞推理锁，不新增等待队列；有界排队仍需单独测并发延迟后决定。取消/请求超时异常继续向上传播，不能变成评分失败降级。已运行的单批推理不能强制中断。

兼容与回退：没有持久化结构或配置迁移；整组回退 ranked_search/relevance/contracts/paging 及相关可选词法接口即可恢复前版行为。不要只回退分页支持而保留新候选列表。模型、数据、令牌、引用存储无需修改；重启会使已有连接重连，临时结果需重新查询。

验证分层：先保存原有 20 项针对性测试基线；增加摘要抑制补查、补查二次上限、12 来源预算边界、忙碌与翻页、超限候选输出无损分页、失效/异库片段、文档范围被 240 条外部命中挤占、取消传播等回归。独立真实模型用 14 个合成案例（含长文本首/尾关键事实）校验阈值判定。真实库仅在隔离副本重放，验证工具候选，不等同于多题 Agent 回答效果验收。
