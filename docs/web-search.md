# 深度 AI 的服务端联网搜索

## 使用与配置

系统设置的 AI 生成配置提供“启用联网搜索”，默认关闭。个人或团队 API 编辑窗口内，每个模型独立配置搜索方式；不是整个 API 共用一种模型能力。两处均启用时，深度 AI 提供搜索工具，由模型决定是否使用。基础检索、增强 AI、摘要不添加搜索工具。系统开关在创建本轮模型客户端时读取，关闭后不强行取消正在运行的请求。

- OpenAI 协议模型选择 Responses 搜索：深度 AI 使用 `/v1/responses` 和 `web_search`，普通聊天与连接检测仍沿用原协议。
- Anthropic / Anthropic Arch 模型选择 Anthropic 搜索：使用 Messages API 的 `web_search_20250305`。
- 模型行“更多 → 测试联网搜索”发起真实的公开资料搜索，返回结果后才能确认当前网关支持。该显式测试可在系统总开关关闭时进行，不会自动开启配置或发送知识库内容。测试结果仅当次展示，不代表长期能力保证。

应用服务器只需访问所配置的 API，搜索和网页读取由上游执行。应用不额外接入搜索服务，也不自行抓取网页。名称相同的模型在不同网关可能不支持相同协议，不能仅根据模型名启用。

## 展示与异常

查阅过程展示搜索/阅读网页状态；网页来源与知识库引用分别显示。仅接受上游结构化返回的 HTTP(S) 来源，不把正文里任意链接当作检索证据。来源标记区分“搜索结果”和“已引用”，保留到会话 trace，刷新或重新打开可以恢复。

保留现有 AI 约束策略及提示词；开启搜索不改变知识库事实的引用要求，也不保证模型每次调用搜索。资料优先模式仍有原先的内容约束，验证联网能力应使用单独测试按钮，并在综合分析模式验证实际问答。

搜索服务返回明确错误时显示失败；没有来源时不伪造来源。HTTP/协议/超时错误沿用既有深度 AI 错误与部分答案处理，不自动偷偷切换到其他模型或普通聊天接口。Anthropic `pause_turn` 保留服务端原始协议块并继续，在原有轮次和时间预算内运行。正式收尾阶段禁止再次调用搜索。

网页工具由上游执行，取消本地请求无法保证上游立即停止计算或计费。`max_uses=5` 是请求提示，当前网关未证实严格执行该限制，不将其作为硬预算。现有应用任务超时和查阅轮次仍有效，但不能中断上游内部某一次搜索。自动重试可能再次触发搜索。

联网测试弹窗的关闭按钮仅收起弹窗。独立的“中止测试”使用 AbortController 断开本次 HTTP 请求，立即显示“已中止测试”，不记录为能力检测失败，也不自动重试。离开配置页时同样断开测试请求。后端监听 HTTP 连接断开事件，断开或达到 90 秒时限后取消测试协程，等待其 finally 关闭模型 HTTP 客户端；不影响其他用户的测试。上游终止计算/计费仍不作保证。该机制不需要任务表或新增权限，兼容旧客户端，但新前端需配合新后端才能取消服务端任务。

## 兼容与回退

启动时幂等创建 `api_model_web` 附表，旧模型缺省关闭；不改写既有模型和用户资料。旧客户端未提交搜索字段时保留已有配置。模型重命名随迁配置，删除时外键级联清理。系统开关保存在 `qa.ai_generation.web_search_enabled`，旧配置缺省 false，旧客户端省略该字段时不覆盖。

回退首先关闭系统总开关，或把对应模型设为不启用；代码回退可保留新增附表，不需要删除表。旧代码忽略附表和新增 trace 字段。普通连接测试不替代原生工具及联网测试；启用 Responses 搜索后应再执行工具检测。

## 本次验证

使用隔离测试目录运行模型配置、修改/重命名、权限、全局开关、流式协议、暂停续传、来源清洗与持久化、问答任务恢复等回归；前端进行 TypeScript 和生产构建检查。

在当前配置网关实测 `glm-5.3`、`deepseek-flash` 和 `gpt-6.1-sol`，均通过新 ToolChat 适配完成本地测试工具与服务端搜索的混合调用（公开 Python 资料，无业务文档）。GLM 和 DeepSeek 本次返回搜索来源但没有结构化引用标记；GPT 返回引用来源。这是该网关当次结果，不代表所有官方接口或其他模型版本均支持。

尚未进行生产服务器测试、浏览器手工整轮问答验证，以及真实上游搜索中途取消的计费验证。未更改现有真实模型配置，启用和本地重启由用户确认。

## 团队调用统计

团队 API 页独立的“调用统计”页签使用 `/admin/api-stats/users`，沿用 `api.stats` 权限。个人 API 页面不变。服务端按 1/7/30/90 天、API、模型、用户名称、是否包含测试筛选；按用户聚合并以 20/50 条分页，支持调用次数、失败次数和最近调用排序。用户明细按 API/模型聚合并独立分页。只查询归属和调用元数据，不返回问题、回答、错误正文或凭据。无归属记录作为未知用户，活跃用户数不包含未知归属。

数据基于当前仍属于团队的 API 及保留日志；删除或转为个人的 API 不纳入。日志关闭和历史清理会导致缺失，不是完整账单；一轮问答可包含多次模型调用。旧接口保持兼容，无数据库迁移。新工具/联网检测归入 `test` 场景，遵守现有测试日志开关；旧测试误记为问答的历史记录无法可靠排除，不回填。Token 未完整采集，不展示 Token 用量或费用。回退前端或代码不修改历史日志。
