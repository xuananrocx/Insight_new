# MCP 优化独立验收

开发侧与下游侧独立测试，不访问对方 Agent 会话、不改对方配置。用户侧使用 Claude Code + GLM，沿用 2026-11-12 原基线报告的原始问题和文档。本文不保存真实知识库编号、凭据或业务正文。

## 测试前核对

服务已加载新代码后重新连接 MCP，初始化的版本是 Insight 版本；工具结果应有 contract_version=2。保留同一知识库内容版本、模型具体型号、客户端版本、系统提示、最大并发、输出字符限额和超时设置。若与基线不同，记录差异。不要为让结果变好临时提高并发、改模型或重建索引。

## 下游效果对比

| 编号 | 用原基线输入执行 | 核对重点 |

| P5 | 固定结果继续页 | 是否只翻快照、不重查；至少测 3 次耗时，记录首查/续页，不比较不同 corpus 的绝对速度 |
| P6 | 四个并行只读请求 | 记录实际配置；busy 与 rate_limited 是否可区分并恢复，不要求所有并发都成功 |

版本冲突、权限撤销、重建索引等破坏性场景仅在隔离样本库测试，不在真实业务库制造变更。复杂问题重复 3 次，报告结果波动，不用单次好运证明改进。

每题建议记录：输入、工具及参数、outcome、coverage、continued kinds、request_id、实际耗时、输出字符数、有效来源数、最终回答、遗漏/错误、引用可核验性。正文如含内部信息，只保留在用户自己的报告中；不要把令牌放进报告。工具行为与回答质量分别判定。

## 开发侧验证范围

独立临时 AMD_DATA_DIR；构造原文、表格、大目录和跨切片命中，执行真实阅读索引及 HTTP/SDK 链路。验证合约、权限、预算、分页无损、稳定来源、版本失效、取消与并发槽。多语言候选测试 mock embedding / vector 返回，只能验证融合和过滤逻辑，不能证明真实 GLM 或 embedding 质量。

命令：

```bash
.venv/bin/python -m pytest -q
.venv-mcp/bin/python -m tests.mcp_gateway_check
.venv/bin/python -m tests.mcp_review_server /tmp/insight-mcp-v2-review.json
# 另一终端；review server 自动使用临时数据，结束后 Ctrl-C 清理
.venv-mcp/bin/python -m tests.mcp_live_check /tmp/insight-mcp-v2-review.json
```

独立功能验证通过后，真实下游收益仍待 Claude Code + GLM 报告确认。未通过项应区分解析缺口、索引失效、查询语言、候选排序、工具理解、引用使用和模型推断，再确定是否需要继续改动。

跨语言排障、版本区分、指定文档、长文末尾事实、Markdown 表格计算和完整字段列举的核心事实正确。额外 161 成员样本按 offset 0/50/100/150 读取四页，最后 next_offset=null，正确包含最后一个成员。答案中的完整 source_id/evidence_id 均可在本会话工具结果核对。所有会话完成且工具未报错，不代表所有答案质量通过。

两次跨文档综合题虽然找到正确来源及数值，仍有将额外执行安排或文档优先级写得过强的问题；无答案题拒绝猜人数，但将“本次未找到”扩大为“全库没有”，并误抄诊断 request_id。没有据此放宽检索阈值或修改产品提示。主 10 次端到端约 31–94 秒，模型 API 等待约占模型/工具合计等待的 89%；速度优化按用户要求留待后续。
