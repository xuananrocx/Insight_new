# 深度 AI 工具整体调研与使用手册

本文为修复前调研快照。随后 1—8 项已实施，当前接口及影响见 [工具使用说明与边界](knowledge-tool-usage.md)；下文 7/9 个工具、范围参数组合和日志错误均记录历史状态，不代表最新接口。

调研日期：2026-09-23。对象：Insight 当前工作区代码及本机生产调用日志。本文用于产品讨论、开发维护和使用效果评估，不改变运行时提示词或程序。

## 1. 定位与主要结论

工具的定位是给 AI 更好的知识库访问方式：发现文档、查找内容、定位原文、连续阅读和回看当前会话。工具负责来源、位置、版本和读取范围的准确性，AI 自主选择调用路径和作答方式。

当前默认注册 **7 个工具**；存在当前会话历史时增加 2 个历史工具，共 **9 个**。知识库工具都是读取操作；要点记录工具更新本次请求内的记录。工具没有联网搜索、命令执行、文件修改、用户管理或知识库授权修改能力。

已观察到的改善：补建阅读索引后，三次同题调用都完整读取 MDSnapshot，减少了此前漏读结构体后半段的问题。尚未解决的问题包括可选参数误填、跨业务搜索结果混杂、表格业务表头识别有限，以及模型对已读资料的解释差异。工具正确定位不能等同于答案已经正确。

日志依据：元数据库中的 AI 调用日志，统计区间固定为 **689～846**，只统计其中 `knowledge_tool` 与 `conversation_history` 场景。本区间跨越工具版本变化，且主要是同一字段问题，不能当作通用基准或严格的改造前后实验。统计中的耗时是本地工具记录耗时，不包括模型选择工具所花的全部时间。

## 3. 工具总览

| 名称 | 功能 | 注册条件 | 是否改变持久化业务数据 |
|---|---|---|---|
| get_kb_overview | 知识库背景、状态和候选目录 | 默认 | 否 |
| list_documents | 按文件名查文档 | 默认 | 否 |
| search_knowledge | 当前知识库全文片段检索 | 默认 | 否 |
| search_document | 文档内及指定范围检索 | 默认 | 否 |
| get_document_outline | 章节、对象和成员目录 | 默认 | 否 |
| read_document | 原文、对象和表格阅读 | 默认 | 否 |
| record_evidence_review | 记录当前问题要点和原文摘录 | 默认，但调用可选 | 不修改知识库；记录属于本次研究状态，调用可写日志 |
| search_conversation_history | 搜索当前会话历史 | 存在 session_id 且有历史轮次 | 否 |
| read_conversation_turns | 读取历史轮次及相邻问答 | 同上 | 否 |

这里的“全库”指本次请求绑定的当前授权知识库，不是跨所有用户、所有知识库搜索。

## 4. 通用调用规则

- 文档编号来自目录或搜索；对象编号来自新版对象目录，不能按名称猜编号。
- `read_ref` 是本轮工具返回的阅读入口，绑定文档版本和相应索引；不由模型自行拼接。
- 分页使用返回的 `next_offset` 或 `next_read_ref`。搜索续页保持查询、模式、范围一致。
- 可选范围参数通过**省略**表示不限制。字符串 `"none"`、`"x"`、`"/"` 都是实际筛选值，不是空值；当前参数校验也不接受 JSON null 代替省略。
- 同时提供章节、对象、工作表时取交集，不是任选其一。
- 搜索结果是片段。目录是导航。读取状态描述文本范围，不判断业务结论。
- 文档在过程中更新、索引重建导致旧阅读入口失效时，需要重新获取入口。

## 5. 六个知识库工具详解

### 5.1 get_kb_overview：了解当前知识库

**输入**：空对象 `{}`。

**输出**：知识库名称、简介、文档总数、已入库/未就绪数量、相关文档目录、目录是否被截断、概览摘要状态。

候选目录按问题和文件名相关性排序，最多 12 条，且有约 4,500 字符的目录容量限制；知识库描述最多 2,000 字符。全局摘要只有快照与当前文档版本匹配时才返回，最多 3,000 字符，否则标记缺失或过期。

**用途**：不了解知识库内容时获取背景和文档入口。

**效果和边界**：减少盲目猜测文件名，但目录不是完整文档列表。概览摘要是背景，不是独立原文引用。调研统计区间未观察到该工具的显式调用，不能据此评价效果好坏；初始化过程也会提供目录背景。

### 5.2 list_documents：按文件名找文档

**参数**：

| 参数 | 必填 | 含义 |
|---|---|---|
| query | 否 | 文件名/相对路径关键词，最多 200 字符；省略或空字符串列出文档 |
| offset | 否 | 分页偏移，默认 0 |

每页最多 30 篇，返回 `documents`、`total`、`next_offset`。匹配使用相对路径的不区分大小写子串，所以目录名也可能命中。

```json
{"query":"ama_struct.h","offset":0}
```

**用途**：寻找某个指南、头文件、版本对应表，取得真实 document_id。

**边界**：不搜索正文、不做语义搜索；空结果只能说明名称未匹配。统计区间未观察到显式调用。

### 5.3 search_knowledge：当前知识库搜索

**参数**：`query` 必填，1～1,000 字符；`limit` 可选，1～8；`offset` 可选，0～10,000；`match_mode` 可选，默认 related。

| 模式 | 实际行为 |
|---|---|
| related | 使用现有检索流程，包含该流程配置的相关性处理 |
| hybrid | 当前全库分支与 related 共用现有检索流程，并不是另外一个独立搜索引擎 |
| exact | 不区分大小写的完整查询子串匹配 |
| identifier | 不区分大小写，并检查英文数字下划线标识符边界 |
| keyword | 增量关键词索引查询，带现有标识符命中排序 |
| semantic | 查询向量检索候选 |

```json
{"query":"连接失败 重试配置","match_mode":"hybrid","limit":8}
```

返回 `evidence`、可识别对象入口 `objects`、匹配说明、`search_scope`、`next_offset` 和状态。证据包含引用编号、文档、版本、片段、坐标、阅读入口以及新索引定位结果。

**定位结果**：

- `exact`：摘要在该文档新索引中唯一定位，阅读入口进入新版原文。
- `ambiguous`：有多个原文位置，最多列出八个候选；超出时标记截断，不默默选一个。
- `not_located`：精确定位失败，保留旧阅读入口，并提供目录提示。
- `index_unavailable`：没有有效新索引，回退旧入口。

**边界**：全库 related/hybrid 底层请求 20 个候选；semantic 候选请求最多 100 个。`next_offset` 是候选池分页，不保证完整枚举全部原文。exact/identifier 仍以已有检索片段为基础，不是原始文件逐字全盘扫描。语义服务失败时，部分分支会回退关键词并说明，纯全库 semantic 分支没有相同的显式降级处理。

### 5.4 search_document：文档内搜索

**必填**：`document_id`、`query`。其余参数为 `limit`、`offset`、`match_mode`，以及可选 `section`、`object_id`、`sheet`。

文档内支持 related、exact、identifier、semantic、hybrid；related 使用文档内关键词相关排序，hybrid 融合关键词与语义结果。与全库 related/hybrid 的实现不同。

最小调用：

```json
{"document_id":15,"query":"MDSnapshot","match_mode":"identifier"}
```

这里的 15 仅来自本次现场数据，其他知识库应使用各自工具返回的编号。

范围调用示例：

```json
{"document_id":29,"query":"num_bid_orders","match_mode":"identifier","sheet":"AMD内部协议沪深北转码字段表"}
```

工作表名称同样应以实际目录为准。按对象搜索时，只添加目录返回的 object_id，不必同时提供 section、sheet。

**范围实现**：先将现有检索片段精确定位到新索引原文，筛选指定范围；跨范围片段只保留交集文本，再排序和分页。只有能够精确定位的片段参与范围搜索。语义分支仍从有限向量候选中筛选，不保证覆盖所有范围内相关内容。

**错误行为**：索引缺失、对象不存在、工作表不存在或多条件无交集均返回错误，不自动扩大范围。省略范围仍可搜索整篇文档。

**实际问题**：最近多次给头文件传入 `sheet:"x"`、`sheet:"/"`、`sheet:"none"`，并猜测 object_id，造成无效调用。工具定义将这些参数标为可选，但当前日志不能确定是模型、代理的 schema 处理还是其他环节促使它填满参数；不能只凭结果判定责任。见第 9 节。

### 5.5 get_document_outline：目录、对象和成员

**参数**：document_id 必填；query、object_id、offset 可选。

按名称找对象：

```json
{"document_id":15,"query":"MDSnapshot"}
```

按已返回对象编号查成员：

```json
{"document_id":15,"object_id":2,"offset":0}
```

第二个示例中的 2 是示意编号，必须替换为真实返回值。查名称时无需提供 object_id；同时提供时会检查名称与编号是否一致。

**新版返回**：sections 列出章节和工作表；objects 列出识别类型、名称、边界状态、字符数、成员数量和 read_ref。查询成员时返回 members 和续页偏移。章节/对象列表及成员目录每页最多 50 条；query 过滤对象名，不会同时把章节列表过滤成同名章节。

**旧版回退**：没有阅读索引时返回旧检索分段目录，不能将其章节编号当作新版范围参数。

**效果**：支持从符号名称直达完整定义。对象提取是启发式结构识别，不是完整语言 AST；标题和表格边界可能只覆盖解析分段。目录不提供字段的业务等价判断。

### 5.6 read_document：按入口阅读原文

**当前模型输入**：只需 `read_ref`。旧的 document_id/version/section/offset 调用仍在内部兼容，但不作为当前主工具参数暴露。

```json
{"read_ref":"<搜索或目录返回的入口>"}
```

**新版阅读**：单次最多约 12,000 字符，长内容尽量在换行处分段；完整中小对象可一次读取。旧分段入口单次约 6,000 字符。两者均受本轮剩余原文预算影响。

| 输出 | 含义 |
|---|---|
| evidence | 实际返回原文及引用 |
| read_status.page_truncated | 本页之后还有内容 |
| read_status.range_complete | 本次已到指定范围末尾，不等于前面所有内容都读过 |
| read_status.parse_completeness | 当前为 unknown，未声称原文件解析无遗漏 |
| coverage.object_complete | 已识别对象的原文范围累计读全 |
| next_read_ref | 当前范围续读 |
| previous_read_ref | 新版入口向前读相邻内容 |
| next_section_ref | 下一章节入口 |

**代码结构**：声明名称及边界来自当前对象索引，修复此前 MDSnapshot 正文附带 MDIOPVSnapshot 声明提示的问题。

**Excel**：从命中行行首进入原文，附带原始行列和值、合并范围和展示首行。`display_header` 是解析展示首行，`business_header_identified=false` 明确未识别业务表头。坐标列表最多 12 行、约 8,000 字符，合并范围最多附带 100 条，`rows_truncated` 表示行列表受限；正文另有分页。不会推断空白值含义。复杂业务区块、多级表头还不能可靠自动识别。

**引用与复用**：同一版本、相同坐标、逐字包含的已发送正文可用 text_reference 指回之前的引用，减少重复发送。不同文档和版本不因文本相似而合并。

## 6. 要点记录工具

### record_evidence_review

名称沿用旧实现，当前是可选记录工具，没有独立模型核验调用，也不是回答前置条件。

输入顶层为 points 数组，一次及累计最多 8 项，每项包括：

| 字段 | 说明 |
|---|---|
| id | 要点编号，最多 40 字符；同编号更新 |
| question | 要点问题，最多 300 字符 |
| status | supported / partial / conflict / unknown，由模型填写 |
| finding | 发现，最多 600 字符 |
| evidence | 最多 6 个 citation + quote 引用摘录 |
| gap | 尚缺信息，最多 300 字符 |

```json
{"points":[{"id":"p1","question":"配置默认值是什么","status":"unknown","finding":"尚未找到定义","evidence":[],"gap":"需要定位配置说明"}]}
```

有引用时，citation 必须来自本次已读原文，quote 必须逐字出现在该引用中且不超过 600 字符。supported 至少需要一条引用，conflict 至少需要两个不同引用。校验失败返回 invalid_review，并保持已有记录不被部分覆盖。

**重要边界**：这些是该工具已有的记录格式要求，不是整条回答流程的强制核验。它只核对引用存在及摘录字面一致，不证明 finding 推理成立。记录可用于容量降级时组织已有材料，不是跨会话长期记忆。

统计区间没有观察到它的独立调用，尚不能证明该工具在目前问题上有实际收益。

## 7. 当前会话历史工具

### 7.1 search_conversation_history

输入 query 必填，实际执行要求非空且最多 200 字符。

```json
{"query":"之前讨论的重试间隔"}
```

搜索范围为当前会话已装入 Context 的历史轮次，采用词项匹配和中文二字片段计分；最多返回 5 条，含 turn_id、顺序、状态和命中附近节选。同分时较新的轮次靠前。没有独立分页参数，不进行向量检索，也不搜索其他会话。

### 7.2 read_conversation_turns

输入 turn_id 必填，offset 可选。返回目标轮次及前后一轮拼接的文本，一页最多 5,000 字符，以 next_offset 续读。

```json
{"turn_id":"<历史搜索返回的轮次编号>","offset":0}
```

两个历史工具共享约 16,000 字符的本轮读取预算。实际计费按结果 JSON 字符数，属于近似控制而非精确 token 限额。

**用途与边界**：用于承接用户之前的要求、参数和决定。历史答案本身不是新的知识库原文引用；这两个工具不是用户级长期记忆，也不能跨用户查看会话。

本次日志统计区间没有观察到历史工具调用，不据此宣称其效果已获验证。

## 8. 工具如何进入实际调用链

1. 请求创建知识库工具集、要点记录状态；有会话历史时加入历史工具。
2. 工具名称、说明、JSON 参数 schema 一起交给模型，正常轮次采用 auto 选择。
3. 模型输出工具调用后，后端校验参数、权限及文档，执行本地读取或检索。
4. 工具结果和错误返回同一条模型会话；模型可继续调用或直接作答。
5. 模型的公开回答实时流式展示。达到预算等结束条件时，现有流程可能进入禁止继续调用工具的收尾请求。

没有强制“概览→搜索→目录→阅读”的调用次序。上述只是执行机制，以下是可选的入口组合：文件已知时直接文档搜索；符号已知时目录查对象后读取；来源未知时全库搜索；追问先用已有上下文，需要时读取历史。

### 现有技术边界

- 默认最大查阅轮数 10；配置可不限轮数。有轮数限制时工具调用总数上限为轮数乘 4。
- 总时长限制默认关闭，启用时默认值 360 秒；单次请求仍有超时和错误处理。
- 原文预算由 qa.deep_ai.context_chars 控制，代码缺省 48,000，数值夹在 8,000～80,000；仓库示例配置可能覆盖它，不能把缺省当作现场配置。
- 上下文容量保护目前额外预留 18,000 token，加上输出预算；它可能早于模型真实窗口触发。
- 连续调用完全相同参数可命中本轮缓存；当前流程仍有重复调用保护。
- 文档访问继续检查授权、成员归属和版本。没有增加越权访问能力。
- 返回 no_match、参数错误、解析未知和 API 网络失败是不同状态。
- API 在正文已输出后断流，目前保留部分答案，不自动重试整段；这是传输恢复策略，与检索是否成功分别排查。

以上是代码中已有行为的记录，不是本次调研新增约束。

## 9. 实测数据与效果

### 9.1 日志统计：689～846

| 工具 | 调用次数 | 平均记录耗时 | 返回 error | no_match |
|---|---:|---:|---:|---:|
| search_knowledge | 27 | 6.97 秒 | 0 | 7 |
| search_document | 26 | 5.51 秒 | 5 | 5 |
| get_document_outline | 7 | 0.20 秒 | 4 | 0 |
| read_document | 12 | 0.37 秒 | 0 | 0 |

其他工具在此区间没有观察到独立调用。平均值混合了模式、缓存状态、版本和文档规模，不能作为性能承诺。no_match 不等于工具失败；反过来，日志 success 字段也不足以判断调用可用，工具结果内的 error 必须单独检查。

### 9.2 已验证改善

**跨业务结果仍存在。** 同名字段搜索可能命中港股、银行间和其他结构。工具现在提供位置和范围能力，但没有证明它已可靠识别每个表格业务区块。

**答案解释仍有差异。** 同一结构读全后，模型仍可能对字段等价、订单簿范围和转码实现作不同解释。增加约束或写死答案不是本文建议，也不能把定位改进包装成语义准确率保证。

## 10. 能力评估与待讨论事项

| 方面 | 当前评价 | 后续调查方向，尚未授权实施 |
|---|---|---|
| 完整代码对象读取 | 已有实际成功证据 | 扩展到更多代码形态，确认启发式边界 |
| 搜索到原文衔接 | 本次样本定位成功 | 观察大型文档、重复段落、旧版本解析差异 |
| 可选范围工具易用性 | 已出现重复参数错误 | 核对实际发给代理的 schema 与模型调用，确认占位值来源 |
| Excel 阅读 | 坐标和合并范围可用 | 业务区块和复杂表头仍需进一步研究 |
| 分页与覆盖 | 返回技术限制和续读入口 | 评估有限候选池下的漏检，不以第一页当全集 |
| 会话和要点工具收益 | 当前样本不足 | 使用对应类型任务再观察，避免凭命名判断价值 |
| 自主性 | 模型可选工具和路径 | 后续优化围绕接口清晰度、数据准确性和性能 |

优先讨论应聚焦工具接口：是否减少一次调用中的互斥参数、如何让范围直接引用已有导航入口、怎样在不猜测用户意图的情况下让错误更易恢复。不能在未确认前静默忽略范围参数，也不应自动扩大搜索并伪装成原范围的结果。

## 11. 排查时如何阅读日志

1. 先按 turn_id 串起同一问题，避免把并行会话的失败与成功混在一起。
2. 看工具 arguments：编号是否来自目录、可选范围是否误填、分页条件是否变化。
3. 看 result 内的 error、status、search_scope、location，而不只看外层 success。
4. 看 reading.artifact、read_status、coverage，确认实际走新索引还是旧入口、对象是否读全。
5. 看 stop_reason，区分自主结束、轮次、上下文保护和 stream_error。
6. 检查答案引用是否对应实际读到的内容；这属于人工调研，不是新增模型核验节点。
