# 全局摘要后台任务

## 用户行为

生成或重新生成全局摘要，始终复用已有有效文档摘要，仅补齐缺失或过期部分。`force=true` 不再重做所有文档。已有文档摘要不因默认模型切换自动失效。

`POST /api/v1/kbs/{kb_id}/global_summary/build` 返回 HTTP 202 和任务，不再同步返回摘要正文。前端通过 `GET .../global_summary/task` 查询最新任务，并在完成后重新读取原来的摘要接口。旧客户端必须同步更新，否则可能把任务响应误认为摘要响应。

一个知识库只能有一个排队、执行或取消中的任务；不同知识库共享一个后台工作线程。刷新或离开页面不会取消任务。管理员或具有知识库管理权限的成员可取消任务；取消在当前模型调用结束后的安全边界完成，取消请求本身不保证上游立刻停止计费。后端重试等待会检查取消信号。

失败、中断或取消后，点击“按当前默认模型重试”创建新任务，复用已完成文档与匹配的分段检查点。检查点按文档版本、片段内容、API 配置/模型和算法版本隔离，不持久化密钥。默认模型变化后不混用其他模型的片段笔记。

## 输入与完整性

优先读取现有且版本匹配的完整阅读索引，避免重新读取重叠的检索片段。无阅读索引时回退到现有向量片段；缺少片段则失败，不静默忽略。新切片保存来源字符位置，只在位置和文本都匹配时移除重叠；历史片段没有位置时保守保留，避免错误去掉 XML 的有意义重复结构。

单段包含分隔符在内不超过配置字符上限，超大片段进一步拆分；字符预算不是模型 token 上下文保证。分层汇总每组最多约 16000 字符，不再只选前 30 份文档。任意分段失败即停止当前任务，不能把部分内容标成全文覆盖；旧全局摘要保留。

首次升级沿用现有 `processed_level=summarized` 的文档摘要，首次复用时建立内容版本记录。这不追溯证明历史生成的覆盖完整性，也不会因此自动重做历史文档。此后新结果持久化文档哈希和摘要摘要值，版本不匹配不复用。

## 超时与结果

系统设置 `llm.request_timeout_seconds` 用于模型网络读取等待，不再被重试层固定 60 秒覆盖。摘要单次调用及重试仍受 300 秒预算约束；整个任务默认 3600 秒，由 `ingest.ai_summary.task_timeout_seconds` 配置。创建任务/查询状态保留前端普通短请求超时，该超时不表示后台任务失败。

单任务最多启动 1000 次摘要逻辑调用（每次还可能有最多 3 次网络重试）。空响应最多一次额外尝试；明确输出截断时允许一次增大输出上限，最高 8000 tokens；JSON 结构错误最多一次重新生成。失败不换 API 或模型。

Anthropic 同步结果拼接全部文本块，并记录块类型、结束原因和文本长度，不把正文写入诊断日志。OpenAI 同步结果携带结束原因；摘要解析使用标准 JSON 解码和字段检查，不依赖未安装的 JSON 修复库。

## 持久化与回退

新增 `summary_jobs`、`summary_versions`、`summary_checkpoints`、`summary_publications`，不删除旧表或旧摘要。任务提交时保存文档版本快照；发布时事务内再次校验快照与取消标记。文档摘要元数据与概念引用在同一 SQLite 事务中更新；向量更新配有持久化回滚记录，异常时恢复旧向量，重启时恢复未完成发布。概念替换移除旧文件引用，保留其他文件的来源。

服务启动时把未结束任务标记为 interrupted，不自动重新调用模型。升级前停止旧同步生成请求并备份 metadata.db；如回退，应先停止新任务，恢复旧前后端配套版本。附加表可保留，旧版不会读取它们；已有摘要仍可读。跨存储发布必须在恢复回滚记录后再回退，不能直接删除 journal 表。

尚未对真实收费模型主动发起验证；空响应的具体上游原因需要用户用新诊断日志验证。完整正文很大的 XML 仍可能需要大量调用，优先复用现有摘要，建议先在小知识库验证。

## 超大文档与生成前预览（2026-10-15）

前端先调用 `POST /api/v1/kbs/{id}/global_summary/preview`，请求体为
`{"full_file_ids": []}`。预览只读取本地索引、摘要与分段缓存，不调用模型。
返回每份文档的处理方式、字符数、可复用分段数、预计调用量及计划 token。
确认生成使用原 build 接口，传入 `plan_token`、`full_file_ids` 和 `budget`。
计划与文档、缓存或当前模型不一致时返回 409，要求重新预览；预估超过预算时拒绝启动。
旧客户端仍兼容，使用安全自动策略及默认预算，不会自动完整处理超大文档。

- 优先复用有效完整摘要；历史摘要沿用原有兼容规则，无法追溯证明历史覆盖完整性。
- 缺失摘要预计超过 12 次调用时默认生成概览；已有有效概览直接复用。
- 概览根据现有阅读索引的正文位置选取最多 12 个窗口（总计最多 18,000 字符），提供准确采样字符数和位置，不声称覆盖所有类别。
- XML 复用既有解析器保留的 `[tag] text` 内容，统计各标签的文本节点，并提供至多 24 种标签的首个样本。不是原始 XML 全节点/属性统计，也不是业务记录总数。通用文件复用阅读索引中的结构对象统计。
- 概览单独保存在新增 `summary_overviews` 表，按文件 hash 和算法版本失效；不会写成完整文档摘要、替换完整摘要向量或概念。全局摘要由程序附加概览来源清单与覆盖限制，检索原文能力不变。
- 预览中可逐份选择完整摘要，原有有效摘要与成功分段笔记仍复用；成功后全局摘要使用完整结果。
- 默认每任务最多 40 次逻辑模型调用，可明确设置 1–1000；空响应/截断后的补偿调用也计入此预算。底层网络重试有独立限制，不计入这里的逻辑调用计数。向量化不包含在估算中。
- 预计调用量不是费用承诺或严格上界：分层汇总受实际输出长度影响。达到调用预算或原有总时长预算（默认一小时）停止，旧全局摘要保留，完成结果可继续复用。
- 分段笔记初始输出额度提高到 4000，截断时最多补偿一次到 8000。没有向未知兼容服务发送未经确认的关闭思考参数。当前模型配置未提供可靠上下文容量，仍使用既有保守的 segment_chars，不依据模型名称猜测容量。

兼容与回退：只新增 `summary_plans`、`summary_overviews` 两张表，不重写原摘要表结构；回退代码可忽略新表。回退前停止活动任务并备份 metadata.db；已经发布的全局摘要正文仍含覆盖说明。概览不提供全文摘要的完整性保证。

验证覆盖：无模型预览、默认超大文档概览、计划过期、预算阻断、概览复用/失效、完整摘要优先、概览升级、采样边界、XML 统计语义、旧客户端和权限回归。
