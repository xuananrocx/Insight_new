# 会话上下文与个人偏好

AI 增强和深度 AI 共用会话上下文。近期保留完整的用户问题和 AI 回答；失败、取消或未完成的历史回答带状态说明。历史讨论、摘要和个人偏好都不作为本轮知识库证据，引用仍以本轮实际查阅的资料为准。

## 请求与存储

- 带 `session_id` 的问答从 SQLite 读取已授权会话，忽略客户端传来的历史副本；有 `turn_id` 时只读取该轮之前的记录，避免当前问题重复或重试时读到后续回答。
- 无会话 ID 的旧 API 调用仍支持 `history`，仅接纳 user/assistant 文本，不产生持久摘要或跨会话检索能力。
- 现有请求入口继续检查账号、会话归属、知识库及 API 权限。记忆模块不另发权限请求；知识库/API 工具原有运行中权限检查保留。
- 数据库 v16 新增 `conversation_summaries`，不修改原始聊天内容。新库和 v15 升级均支持；旧会话继续提问时按需生成摘要。
- 摘要保存覆盖轮数、原文指纹、知识库 ID、版本及时间，最多保留 10 个版本。读取和提交时核对覆盖原文；历史编辑、删除、知识库变更会使旧摘要失效。删除会话通过外键级联清理摘要。

## 摘要与预算

历史按 token 估算预算裁剪，而不是固定保留六轮。近期问答尽量整轮保留；单轮超长时保留节选并明确标记，深度 AI 可通过历史工具读取原文。

较早的问答超出预算时，采用“旧摘要 + 新增原文”增量更新，记录目标、环境、决定、尝试结果、待解决问题及用户纠正，并要求保留原始轮次 ID。摘要是有损的模型生成内容，不能替代原文。单条原文超出摘要输入预算时提供带标记的节选，不会无限阻塞之后的摘要更新。

一般在后台更新，同一会话不重复启动任务，全局最多 2 个摘要任务。超过并发上限时延后到后续提问。首次恢复很长的旧会话且多数历史无法直接携带时，最多同步等待 30 秒，随后继续作答，后台任务可继续执行。同步 `/qa/ask` 在等待超时后会取消本次摘要任务并使用已有上下文。

摘要调用使用发起请求时绑定的 API 和重试次数，不自动换用其他用户的 API；总预算 90 秒。API 返回失败或中断时不保存部分摘要，保留旧摘要及近期问答。服务关闭会取消未完成的后台摘要任务；下次提问可重新触发。

配置 `qa.conversation_context`：

```yaml
context_window_tokens: 65536
history_tokens: 8000
summary_input_tokens: 10000
summary_tokens: 2400
```

这些配置缺省时也采用上述值，不要求覆盖已有用户配置。`context_window_tokens` 是配置值，**不是自动探测出的模型容量**；使用较小窗口的模型时需要调整。当前计数采用 UTF-8 长度估算，非供应商精确 tokenizer 或账单用量。历史组装预留问题、系统指令、知识库/工具内容及输出空间；模型实际请求前还记录总输入估算及超预算警告。既有知识库内容的预算仍由原检索/深度 AI 配置控制。

## 当前会话历史工具

新会话没有历史时不提供历史工具，也不附加空的历史/偏好指令；有实际历史或个人偏好时才加入相应上下文。

深度 AI 增加：

- `search_conversation_history(query)`：通过关键词与中文二元词片段搜索当前会话快照，最多返回 5 个匹配片段。
- `read_conversation_turns(turn_id, offset)`：读取指定轮次及前后文，每页最多 5,000 字符，支持 `next_offset` 续读。

工具不接受用户 ID、其他会话 ID 或文件路径；不能搜索其他用户、其他会话。历史读取共享本轮工具调用次数和时间预算，另有约 16,000 字符的累计返回预算。结果明确标为历史讨论，不加入知识库引用来源。AI 增强使用同一摘要和近期问答，但没有原生历史工具调用。

## 个人偏好

设置页增加“个人偏好”，默认开启、内容为空。通过弹窗编辑 Markdown，最多 4,000 字符，仅用户手动保存，AI 不自动修改。可以停用，或清空后保存。

文件位于用户数据目录 `preferences/<用户 ID 的 SHA-256>/preferences.md`。首行是保存开关与版本的内部注释，其后为 Markdown 正文。接口不允许指定其他账号或路径；原子替换文件，并用版本检查防止旧页面覆盖新内容。管理员的接口也只读取自己的文件。

偏好是默认习惯，当前问题中的明确要求优先；不能覆盖系统权限。读取失败不会使回答失败，会记录警告并跳过偏好。

## 设置与日志

“显示上下文使用情况”默认关闭，开启后在回答旁显示可展开的信息，包括近期轮数、摘要覆盖范围、偏好加载状态及历史读取次数。信息写入该轮 trace，重新打开会话仍可查看。

- **系统日志**：上下文组装开始/完成、各部分 token 估算、裁剪原因、模型请求总输入预算、摘要开始/完成/失败/过期丢弃/并发延后、历史工具执行及偏好读取异常。关联用户、会话、轮次及上下文请求编号。常规日志不记录聊天或偏好全文。
- **AI 调用日志**：`conversation_summary` 显示为“会话记忆 · 自动摘要”；`conversation_history` 显示为“会话记忆 · 历史查阅”。沿用现有账号隔离、日志字段开关、耗时和重试诊断，详情可跳转会话。用户启用消息/响应记录时仍按原规则保存内容。
- **操作日志**：修改、启用、停用个人偏好使用中文动作名称，不记录偏好正文。

## 深度 AI 查阅设置

设置页按账号保存查阅选项，并随本轮请求传入 `deep_ai_options`：`max_rounds` 默认 10、`null` 表示不限轮数，正整数不设固定上限；`time_limit_enabled` 默认 false，`total_timeout_seconds` 预设 360（6 分钟）。未传入时使用 `qa.deep_ai` 配置及同样的缺省值。总时长限制关闭后没有整次查阅倒计时，单次模型调用仍有 180 秒预算及既有网络超时/重试保护；开启后在总预算内为正式回答预留时间。

不限轮数仍受证据容量、模型上下文估算容量、重复查阅及连续三轮无新资料保护，可手动停止。最后几轮提示优先核实字段定义和适用范围。字段检索返回精确命中与本次未命中字段；未命中不代表不存在。章节标签明确显示银行间/外汇等不同范围时返回核对提示，不自动推定市场映射关系。

## 验证

自动化测试覆盖完整问答、服务端历史来源、跨用户隔离、工具参数范围和分页、摘要持久化及过期丢弃、超长单轮、失败降级、v15 数据迁移，以及原有检索模式、API 权限和重试兼容性。自动化测试使用模拟模型响应，不访问真实付费 API；回答质量需另外使用隔离数据进行真实模型抽查，不能由功能测试保证。
