# API 多模型与会话选择迁移

## 行为和范围

每条 `auth_providers` 记录继续保存一套连接和加密密钥；`api_models` 保存模型 ID、显示名称和检测状态。团队授权按连接授予，覆盖连接内配置的模型。新增模型、普通配置编辑不自动修改个人选择；明确修改已有模型 ID 并确认影响时，按下述规则同步关联选择。

`api_preferences` 保存用户的默认模型与重试次数，默认连接继续使用 `auth_users.default_provider`。`api_session_selection` 保存会话的连接与模型；新会话固定创建时的个人默认，旧会话首次提问时初始化，已有选择失效时不自动回退。`api_job_models` 补充上传任务实际选择的模型 ID，不包含密钥。

每次请求用配置快照，但调用前仍校验用户、授权、连接启停和模型是否存在。移除模型或停用连接会阻止后续调用，已发送的外部请求无法撤回。不会跨 API 或跨模型自动切换。标题、深度 AI、普通 AI 使用相同的选择入口；系统向量模型不受影响。

## 初始化与兼容

`accounts.init_auth()` 调用 `api_models.init_schema()`，以可重复执行方式创建附加表。已有 API 迁移出一个模型，原始 ID、加密密钥和团队授权保持不变；已有默认连接映射到原单模型。新账号首次初始化导入的连接也执行此迁移。停用项不重新启用。

旧 `chat_model` 字段作为明确的兼容模型保留；只传 Provider ID 的旧调用使用该模型。如果该模型被新版删除，旧调用明确失败，兼容模型不会自动改为列表中的其他项。旧客户端更新单模型配置仍可使用 `chat_model`；对已有多模型配置，省略模型列表不会删除其他模型，尝试通过旧字段更换多模型配置的兼容模型返回 409，要求使用新版管理。新版请求显式发送 `provider_id` 和 `model_id`。

迁移不猜测历史回答的模型。新回答的 `used_provider` 包含 API 名称及真实模型 ID，调用日志还记录 Provider ID 和模型字段。会话导出不包含连接凭据；导入到其他账号不继承原账号的私有 API 选择。

检测结果仅代表上一次检测，不是服务健康保证；修改地址、协议或密钥后失效。模型记录带配置版本，旧检测在连接修改、模型移除再添加后不能覆盖新状态。

## 发布与回退

1. 停止接收新任务，等待当前生成和上传处理结束。
2. 停服务后备份完整数据目录，至少同时保留 SQLite 数据库（含一致的 WAL 状态）和 `credentials.key`。运行中只使用 SQLite backup API，不能直接复制正在写入的数据库文件。
3. 在隔离的数据副本验证启动迁移、旧默认、团队授权及模型调用选择；部署固定提交的候选构建，不能在生产直接构建。
4. 上线后检查个人默认、失效提示、团队管理和聊天选择。真实联网检测是明确的单模型操作，可能产生服务商用量。
5. 如需回退，停服务并恢复升级前配套的数据备份和旧代码／镜像。新多模型、会话选择和检测记录在旧版不可表达，不能把“切回代码”视为完整回退。恢复旧备份会丢弃备份后的业务更改，执行前必须确定保留方案。

本次仅本地开发；生产服务器未部署。备份和测试数据不得提交 Git。

## 模型 ID 编辑关联修复（待验证发布）

- 显示名称仅改变展示，不改变模型 ID、默认选择、会话选择和检测状态。
- 编辑既有模型时携带 `original_model_id`，明确指定旧 ID 到新 ID 的关系；删除后添加不推断为改名，删除仍使原选择失效，禁止自动换模型。
- 可管理的 API 返回 `edit_version`。保存前向 `POST /providers/{pid}/edit-preview` 发送同一份编辑内容，获取各模型涉及的默认用户数、会话数及 `confirmation_token`；团队 API 统计全部关联用户，但不返回其他用户身份或会话 ID。
- PUT 保存携带原 `edit_version` 和预览的 `confirmation_token`。事务内重新校验配置版本及影响集合，变化时返回 409，重新打开编辑后确认；多处独立改名支持，合并、交换 ID 或重复使用原 ID 拒绝。
- 同一事务更新模型目录、个人默认、已保存会话选择和旧 `chat_model` 兼容字段；保留显式容量配置，新 ID 的检测状态清空。任一步失败均回滚。保存默认、保存会话选择、冻结新会话默认也在写事务内校验，防止旧选择在改名后重新写回。
- 历史回答、调用日志、任务模型快照不改写；运行中请求仍校验旧模型，可能中断。任务按已有恢复流程确认使用模型，保留已完成结果。其他标签页/团队用户复用已有权限版本刷新（最多约 10 秒或窗口聚焦），刷新前旧 ID 请求明确失败，不自动切换。
- 新建会话尚未发送的临时模型选择不属于已保存会话，失效后用户重新选择。已损坏的历史关联不自动猜测映射；176 待下次版本升级时单独核对并修复。
- 不增加数据库表或列，不自动批量迁移存量数据。回退代码不会撤销用户已确认的改名；若要撤销数据操作，须明确逆向改名或按发布备份恢复，不能直接覆盖运行中的数据库。
- 旧客户端未传新协议字段时保留原有行为，不承诺自动关联迁移；新版前端必须与新版后端配套使用。
