# 单团队账号与 API 管理

本版本关闭公开注册。首次访问进入初始化页，之后账号由管理员创建。

## 首次使用

1. 安装 `requirements.txt`，构建前端，按原方式启动服务。
2. 从服务器用户数据目录读取 `setup-token.txt`，在初始化页输入令牌、管理员用户名和至少 12 位密码。没有预设管理员密码；令牌不会通过接口返回。
3. 初始化会把已有知识库、会话、AI 日志、反馈和上传任务归到该管理员，原全局聊天 API 迁入其个人 API。不会重新建立向量索引，也不会改变已有 ID。
4. 初始化事务开始前创建 `before-accounts.sqlite3` 备份（包含 WAL 数据）。初始化成功后删除令牌文件。
5. 管理员在“系统管理 → 用户管理”创建账号并交付初始密码。新用户首次登录必须修改密码。

默认数据目录：Windows `%LOCALAPPDATA%/AI-Assistant`；Linux `~/.local/share/AI-Assistant`。可用 `AMD_DATA_DIR` 指定。已有目录沿用原位置。

## 权限

| 角色 | 范围 |
| --- | --- |
| 超级管理员 | 首个管理员自动获得；受保护的角色，不能编辑、停用、删除，至少保留一个启用账号 |
| 系统管理员模板 | 用户、角色、团队资源和系统设置管理；可以按需编辑或替换 |
| 普通成员模板 | 个人文档、分析、反馈、AI 日志，个人 API 和私有知识库创建；可按需编辑 |
| 知识库只读成员 | 查询、提问、读取该库内容 |
| 知识库编辑者 | 只读权限，加上传、扫描及修改文档 |
| 知识库管理员 | 编辑权限，加重建、修改库信息、授权自己拥有的查询/编辑权限；导出、下载需另行授权 |
| 知识库所有者 | 全部知识库权限，包括任命知识库管理员、删除自己的库 |

系统管理员身份不会自动授予其他用户的会话、个人 API、AI 日志或私有知识库读取权限。服务器维护人员仍有能力直接读取服务器数据库，这不属于应用账号权限。

自定义角色支持创建、复制、编辑、停用和删除；一个账号可以有多个角色，启用角色的功能权限取并集，不使用角色继承。有成员或关联授权的角色不能直接删除。委派功能权限不能超出操作者自身范围，普通管理者不能管理超级管理员；不允许通过用户管理修改自己的角色、状态或密码。

菜单和操作权限由固定的权限目录定义，页面入口和后端接口同时校验。提问、本人会话、个人设置与已授权知识库的访问为基础能力；四种检索/回答模式不单独收费或设角色门槛。知识库授权页显示本人拥有或可管理的资源，无资源时为空。

知识库授权可在详情页或“系统管理 → 知识库授权”配置，支持指定用户和指定角色。查询、编辑、管理、导出知识库、下载原文件分别控制。多个允许来源取并集，用户级“明确禁止”优先；移除一条授权不代表撤销其他来源。变更前提供影响预览与最终权限解释，保存时校验预览版本，避免覆盖别人的新修改。

默认新建私有知识库。所有者可以显式转为团队知识库；团队资源管理者可修改团队库的归属、状态和授权，但没有隐含的查询或下载权。私有库不自动向团队管理员开放。转回私有需先移除共享授权，转移所有者不转移原用户的会话或个人 API。停用知识库优先于全部授权，所有者和团队资源管理者仍可通过授权页重新启用。

撤销授权后，原用户仍可查看和导出自己的历史会话、答案、引用快照；新的提问、检索、重新生成及原文件下载均重新校验。正在输出的回答也会检查授权变化；已发送到外部 API 的请求和已交付内容无法撤回。后端下一次检查即时使用新权限，前端每 10 秒、回到窗口时及本地权限修改后刷新权限并清理旧查询缓存。

停用账号、管理员重置密码和用户改密均撤销登录会话。密码用 Argon2id 保存。登录使用 12 小时有效的服务端 Cookie 会话，写操作校验 CSRF，登录有尝试频率限制。

## 个人 API 与团队 API

- 管理员也有自己的个人 API，和团队公共 API 分开。
- 团队 API 的查看、配置管理、使用授权、汇总统计分开控制。按用户或角色分配调用权，管理员同样需要调用授权；管理配置不自动获得调用权。配置在“系统管理 → 团队 API”，个人设置仅管理个人配置和选择已授权 API。
- 地址不设域名白名单，支持自定义 HTTP(S) 地址和内网网关。个人与团队 API 使用同一规则。
- API 密钥加密保存在数据库中，页面只显示“已配置”；编辑留空保留原密钥，不返回明文。
- 用户选择默认 API；聊天输入区也可以切换。每次提问固定该次请求的 API 和配置，规划、回答、检查使用同一份配置。权限仍会重新校验，撤销后不会自动换用其他人的 API。
- 上传和重建中的 AI 摘要使用发起人的 API，任务记录发起账号与 Provider ID。无可用 API 时保留文档处理及向量化，跳过需要 AI 的部分；不会借用管理员密钥。中断任务需本人重新恢复，不在重启后自动付费调用。
- Embedding 和 reranker 是系统统一配置，与个人聊天 API 分离。原配置文件中用于系统向量化的配置保留；新增个人/团队聊天凭据在加密库中管理。

备份时必须同时保留数据库和 `credentials.key`。丢失该文件后无法解密数据库中的 API 密钥。Linux 文件以仅当前用户可读写的权限创建；部署时应限制整个数据目录的访问权限。

## 日志与旧反馈

AI 调用日志按调用用户隔离，包括详情、统计和批量删除。

系统日志（`/logs`）读取服务器的 `app.log` 及轮转文件，提供运行日志、错误堆栈、自动刷新、下载及清空功能。查看和下载需要 `logs.view`，清空需要 `logs.clear`；日志级别修改仍需要 `system.edit`。入口由个人设置中的「在侧边栏显示系统日志入口」控制。

操作日志（`/admin/audit`）独立记录账号、角色、授权及 API 配置操作，操作名称与详情以中文显示，支持中文搜索；需要 `audit.view`，清理需要 `audit.clear`。清理调用独立的 `/api/v1/admin/audit` 接口，两类日志不会互相清空。操作日志不记录聊天正文或密钥。

升级时超级管理员获得新的系统日志权限；未定制的系统管理员模板一次性补齐新权限，已定制的角色由管理员手动授权。之后撤销的权限不会因重启重新授予。

团队 API 统计只显示升级后已保留调用日志的调用次数、失败次数等汇总，不包含用户的问题、回答或聊天会话。关闭日志记录或删除个人调用日志会影响汇总；当前调用链未采集服务商 Token 用量，因此不是计费账单。

升级时旧管理员/成员映射到初始角色，旧知识库和 API 成员授权迁入新授权表，账号 ID、密码、会话和知识库 ID 保留。迁移标记确保重启不会恢复已删除的授权或角色。服务器本地管理员有操作数据库及密码恢复的能力；应用中的管理员不能直接浏览他人聊天，但密码重置本身属于账号接管能力，必须仅授予可信管理员，并记入审计。

旧反馈集合没有可靠的知识库归属，不再参与问答检索。反馈列表归到原数据管理员，新反馈只对提交人可见；本版反馈确认不再把聊天答案写入全局检索集合。

## 部署与恢复

线上建议以前端/API 同源方式部署并使用 HTTPS，Cookie 自动在 HTTPS 请求下启用 Secure。反向代理需正确转发协议；Uvicorn 只信任实际代理地址的 forwarded headers，例如本机代理使用 `--proxy-headers --forwarded-allow-ips=127.0.0.1`，不要信任任意来源。

保留单应用实例及 SQLite 部署即可。访问不再开放给未登录客户端，旧的 Streamlit/脚本客户端也需要使用登录会话和 CSRF 请求头。

服务器本地密码恢复（密码交互输入，不出现在命令行参数）：

```bash
python -m src.core.manage_accounts 用户名
```

恢复后原登录失效，下次登录必须再改密。此命令不启用已停用账号，也不变更角色。
